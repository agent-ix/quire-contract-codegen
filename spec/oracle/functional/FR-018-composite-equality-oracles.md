# FR-018: Generate exact complete-V1 composite equality oracles

## Description

When a caller supplies an admitted `ContractPackageV1`, an optional
package-bound admitted identity capability, and a set
of equality expression nodes, the code generator shall emit a deterministic Rust
oracle crate whose functions decide each node by reconstructing the item's
`TypeEnvironment` and calling the QSV declaration/equality owner's
`TypeEnvironment::check_equality` and `CheckedEquality::evaluate` with a
caller-supplied `Meter`. It never compares two values structurally, and never
copies a resource charge or a planned pair count.

This is the composite/structural equality slice of complete-V1 oracle
generation. [FR-014](./FR-014-exact-scalar-oracles.md) is its scalar sibling.
It refuses model and relation nodes with the typed blocker whose wire value is
`agent-ix/quire-spec-language#120`, temporal and protocol nodes with the one whose
wire value is `agent-ix/quire-spec-language#121`, and function
application is generated by [FR-021](./FR-021-function-application-oracles.md)'s
own entry point through `CheckedPackage::call`. This requirement's entry point
admits no `call` node and refuses the function family with the typed blocker
whose wire value is `agent-ix/quire-contract-runtime#34`.

The runtime carries no structural equality on `Value`: the FR-149 relation
reached through `check_equality`, `plan_equality` and `CheckedEquality::evaluate`
is the only equality, and it is the only relation that is metered, that is
correct for signed zero, for decimal values retained at differing scales and for
cross-universe references. Generated oracles therefore call it and decide
nothing themselves. Agreement with the quire-spec-language value authority is
outside CG's boundary and not claimed by CG (FR-014-AC-47); generated-oracle
against QSL agreement is owned by quire-integration IR-842.
[FR-014](./FR-014-exact-scalar-oracles.md) owns the integer and Boolean `eq`
and `ne` nodes and emits this same relation for them.

A `CheckedEquality` has no public constructor: it is obtained only from
`TypeEnvironment::check_equality`. The static stage therefore runs twice — once
in the generator, which refuses the item if it does not admit, and once in the
generated function, whose refusal is reported as
`Outcome::Refused(Refusal::CheckedInvariant { cause })` rather than unwrapped.

That second stage must include `TypeEnvironment::check_type` on both operand
comparison types, before `check_equality`. `check_equality` consults the
environment only through `contains_ieee`, which treats a composite key absent
from the environment as bearing no IEEE value and returns `false`; and
`CheckedEquality::evaluate` takes no environment at all, comparing the caller's
two values directly. Without `check_type` the emitted function's
prepared environment therefore decides almost nothing, and an environment
that declares none of the item's composites still completes. `check_type` is the
runtime's own check that every named declaration exists, that every
`Reference<T>` names a model object type, and that no set, bag or ordered set has
an IEEE-bearing element type; requiring it is what makes the second stage a stage
rather than a formality.

The admitted-context ABI and direct-owner migration below are PLANNED until
CG implementation, native generated-code controls and independent review
qualify them. Upstream facade availability is not a CG acceptance result.
The existing record, tuple, recursive closure and collection behavior remains
required; the enum-only facade does not justify withdrawing those routes.

## Inputs

- An admitted `ContractPackageV1` from Contract IR's FR-330 lowerer and strict
  reader, with the caller's complete root-position request and the positions
  of the equality items in it. Its retained checked-V2 graph supplies the
  equality expressions and declaration closure below.
- `Option<&qsl_replay::AdmittedContext>`: `None` permits genuinely
  context-free reconstruction and existing precise early refusals that need
  no nominal key. `Some` is the immutable genuine capability returned beside
  the original compiled package by root `qsl_replay::compile_admitted`; its
  `package_id()` must equal `ContractPackageV1::wire().package.source.package_id`,
  the original checked-package identity, not the lowered package's `identity`.
  Presence grants identity lookup only; absence grants no source authenticity.
  Every reached nominal-key reconstruction requires `Some`, as Behavior
  specifies. The native `OriginalCompositeEqContext` route remains stricter:
  authentic source, original library lock, request-admitted limits and exact
  full original-package comparison remain mandatory before its request
  exposes a genuine context, and that route always supplies `Some`.
- A request of items, each naming one checked `expression` node of semantic form
  `binary` and one typed equality descriptor: an `EqualityOperator`
  (`Equal` or `NotEqual`) and two `EqualityOperand`s, each either
  `EqualityOperand::typed(source)` or `EqualityOperand::converted(source,
  target)`.
- The declaration closure reachable from each operand's `semantic_type`:
  `composite_type` nodes of form `record`, `tuple`, `option`, `sequence`, `set`,
  `bag` and `ordered_set`, their `scalar_type` leaves, and the `bounded_domain`
  nodes those types need.
- A caller-selected per-item type-resolution work limit. When omitted, its
  published default is 65,536 entries; callers may raise it to fit larger
  admitted packages. Its setting name is
  `cg.equality.type_resolution_work_units`.
- A caller-selected generated-source byte limit for this request. Its default
  is 1,048,576 bytes, matching the current `MAX_GENERATED_SOURCE_BYTES`.
  A caller may raise it for a larger admitted oracle using
  `cg.equality.source_bytes`.
- Direct owning dependencies named by this repository's `Cargo.toml`:
  `quire-exact` for kernel values, types, metering and outcomes;
  `quire-semantic-value` (QSV) for declarations, equality and enum indexing;
  root `qsl-replay` for the opaque admitted enum context. Contract Runtime's
  `exact` module is used only for functions it still owns, never as a
  re-export facade for removed owner APIs.

As in FR-014, the V2 transport carries each application term's `operation`
member — its catalogued identity, its laws and its mode — so the IR does say
whether a node's operator is `=` or `!=`. This generator's classifiers do not
read it. The law a generated oracle implements is therefore the caller's: every
claim marks its operation `caller_declared`, and the claim map carries the typed
blocked item "operation identity not consumed by codegen's generators".
Downstream obligations must not treat a caller-declared operation as checked.

A declaration is read from the `composite_type` node's `aggregate` body. The
generator interprets these checked semantic term structures; QSpec's recursive
record fixture supplies the optional-field and bounded-sequence forms:

| Form | Members |
|------|---------|
| `record` | one `binding` per field in declaration order: its `name` is the field name. A required field's value is a `reference` to its type node. An optional field's value is an `aggregate` containing one `binding` named `optional`, whose value is a `reference` to an `option` composite node; the payload of that node is the field's `ValueType`, and the field is `Presence::Optional` |
| `tuple` | one `reference` per position, in declaration order |
| `option` | one `reference` to the payload type node |
| `sequence` | one `reference` to the element type node; a `collection_bounds` `bounded_domain` node whose `semantic_type` is this sequence node supplies its cardinality when the field references that bound node |
| `set`, `bag`, `ordered_set` | a `reference` to the element type node, then a `reference` to the `collection_bounds` domain node |
| `collection_bounds` | two `binding` members, `min` and `max`, each carrying a canonical decimal `integer` literal; for a bound over `sequence`, its `semantic_type` names the sequence node |

A member's type node is a `scalar_type` leaf, whose bounds are the `bounded_domain`
nodes over it, a `bounded_domain` node itself, or a composite node. A scalar
`bounded_domain` reads as FR-018-AC-16 states; `collection_bounds` over a
`sequence` reads as FR-018-AC-27 states. A `text_bounds` node binds the text
profile the checked operation catalog's leaf rule reads.

For the bounded numeric tuple controls, [QSL FR-092](ix://agent-ix/quire-spec-language/FR-092)
requires each bounded type reference to name its `bounded_domain`, not its
base scalar. The public generator controls SHALL reconstruct those genuine
owner-emitted members with their exact bounds, order and rounding. The
legacy base-scalar/domain equivalence and malformed-member resolver controls
SHALL remain separately labelled private defenses under AC-16; they do not
establish public genuine-context acceptance. This allocation does not change
unbounded Integer member semantics or associate an unrelated sibling bound
with a member.

For the recursive-record controls, the exact external QSpec fixture SHALL
remain authoritative strict-reader and shape evidence. Public generation
SHALL use independently authored source with the same required List/Tree
shapes and its own unchanged checked package and genuine admitted context.
Appending equality items to the external fixture does not authenticate the
extended package or supply its context. Private type-resolution controls
SHALL retain the exact fixture-shaped assertions and defenses separately;
neither those controls nor a skipped external-fixture check count as public
generation acceptance.

A declaration or case key SHALL be the original checker-issued key selected
through its owning admitted lookup. Equality with the corresponding V2 wire
identity is retained, including its domain; it is not permission for CG to
hash a preimage, decode a digest into `NodeKey`, or emit a key constructor.
A generated identifier literal is a facade `WireNodeId` used for lookup.

For enums, the generator SHALL call `AdmittedContext::enum_declaration` and
`enum_case`, verify the declaration's qualified name and ordering against the
selected IR node, and use all `AdmittedEnum::cases()`, including unused cases.
QSV `EnumDeclaration::new` receives that genuine declaration key, ordered flag
and complete case names. Each `EnumDeclaration::member` receives the exact
case key returned by the facade. Every resulting `EnumValue` is recorded in
one `EnumMemberIndex`; its `variant()` and `position()` supply exact enum shape
variants and canonical positions. A position, spelling, array index or used
literal set never supplies identity. QSV takes supplied keys as given; its
constructors and `TypeEnvironment` do not authenticate a caller-made index.

The published facade currently supplies enum lookups only. A record or tuple
`CompositeDeclaration` still requires its genuine owner-issued `NodeKey`.
Complete migration of those routes requires an owning composite/general-key
lookup or prepared composite capability; passing a record id to
`enum_declaration` is not that capability. This residual owner gap authorizes
neither backend key construction nor a new `Unsupported` regression for an
existing record/tuple route. The existing closure obligations remain pending
qualification through the actual owning capability.

## Outputs

- A generated crate: `Cargo.toml` (`publish = false`, direct exact/QSV
  dependencies, and root `qsl-replay` for admitted-context lookup) and
  `src/lib.rs`. The single `core/profile` manifest authority supplies normal
  Git branch-main dependencies; consumer lockfiles perform ordinary resolution.
- One public opaque `PreparedEqualityEnvironment<'ctx>` type whose private
  fields retain `Option<&'ctx qsl_replay::AdmittedContext>`, expected
  original package and item/descriptor binding, admitted QSV `TypeEnvironment`,
  complete genuine `EnumMemberIndex`, and reconstructed operand descriptors.
  No public struct literal or raw-index constructor can create this capability.
- Per item, the concrete generated ABI is:

  ```rust
  pub fn environment_symbol<'ctx>(
      context: Option<&'ctx qsl_replay::AdmittedContext>,
  ) -> Result<PreparedEqualityEnvironment<'ctx>, EnvironmentError>;

  pub fn oracle_symbol(
      prepared: &PreparedEqualityEnvironment<'_>,
      left: &quire_exact::Value,
      right: &quire_exact::Value,
      meter: &mut quire_exact::Meter,
  ) -> quire_exact::Outcome<bool>;
  ```

  `symbol` denotes the existing deterministic per-item generated symbol.
  Constructors and descriptor/module helpers thread this same optional
  capability. A nominal recipe requires genuine context before key lookup;
  a completely context-free recipe may publish a prepared value retaining
  `None`. The constructor checks a supplied context's expected original
  package identity before reconstruction, even for primitive recipes, and
  publishes no partial value on failure. Expected package/item/descriptor
  binding stays private and checked in both cases. Recorded package identity
  without context binds the recipe; it does not authenticate source.
- Generated `EnvironmentError` SHALL distinguish
  `MissingAdmittedContext { declaration: qsl_replay::WireNodeId }`,
  `ContextPackageMismatch`,
  `Lookup(qsl_replay::AdmittedLookupRefusal)`, `Declaration` retaining the
  QSV `EnvironmentFailure`, and `Reconstruction(ReconstructionError)`.
  QSV admission's semantic refusal and resource failure remain distinguishable
  through their original typed causes. `ReconstructionError` keeps the
  payload-free numeric/text/cardinality variants `Integer`, `Interval`,
  `Rational`, `Decimal`, `Text`, `Cardinality`, `Enum` and `Composite`.
  `Enum` reports failed QSV enum reconstruction after genuine lookup.
  `Composite` reports an invalid retained composite WireNodeId literal or
  a genuine composite lookup whose record/tuple form or qualified name
  disagrees with the retained emitted recipe. Neither condition constructs
  or substitutes a key. The facade's Unknown, Foreign and WrongKind lookup
  refusals remain `EnvironmentError::Lookup` with their original typed
  details, never `Enum` or `Composite`. Missing context and package mismatch
  keep their own EnvironmentError variants; QSV environment admission keeps
  `Declaration(EnvironmentFailure)`. Numeric, text and cardinality
  reconstruction helpers keep their existing signatures.
  No failure is repaired with an empty index, default value or substituted key.
- A typed claim map with one entry per requested item: node id, Contract IR
  semantic id, package id, semantic type, source map, claims, the reconstructed
  declaration closure and its keys, the selected `EqualitySchedule`, operation
  identity with its `caller_declared` provenance, and either the generated
  symbols or the typed refusal; plus the map-level blocked items.

## Behavior

### Admitted-context ABI

The public generation signature SHALL be:

```rust
pub fn generate_composite_equality_oracles(
    package: &ContractPackageV1,
    admitted: Option<&qsl_replay::AdmittedContext>,
    requested: &[ContractRequestPosition],
    positions: &[usize],
    items: &[CompositeEqualityItem],
    limits: CompositeEqualityLimits,
) -> Result<CompositeEqualityOracles, OracleGenerationError>;
```

After the existing work-setting and whole-request accounting/position
checks, `Some` with a mismatched source package SHALL refuse the whole
generation as the existing typed context mismatch before item classification,
including primitive-only or empty requests. An explicitly wrong capability
is never treated as `None`. Generated preparation applies the same supplied
context mismatch check before reconstructing any descriptor.

When traversal reaches the first operation requiring an enum, record or
tuple identity, `None` SHALL refuse only that item as
`CompositeEqualityRefusal::MissingAdmittedContext { type_node_id }`, naming
that nominal declaration, without constructing a key or emitting its symbols.
Generated preparation of a nominal recipe with `None` SHALL return the
corresponding `EnvironmentError::MissingAdmittedContext` before lookup or
partial publication. Both operands' source types and conversion targets,
all nested Option payloads and collection elements, record/tuple fields and
recursive closure edges are subject to this rule. An outer structural
wrapper or primitive source type cannot hide a reached nominal target.
A present enum-only capability still does not supply the record/tuple owner
lookup missing above; optionality does not resolve that owner gap.

Capability demand SHALL occur in the existing charged traversal, immediately
before nominal identity reconstruction/lookup, not as a preflight scan of
outer tags, all descriptors or the complete context. Existing precise
key-free classification and descriptor refusals remain earlier where the
original procedure makes them earlier. Work charges, first-denied-entry and
cycle precedence, deterministic request/descriptor order, source-byte limits
and sibling isolation remain unchanged. A failed lookup or absent required
capability never becomes `Unsupported`, a default key or omitted declaration.
Unknown declaration, unknown case and Foreign package lookup failures retain
their original typed distinctions and fields. Claim-map serialization may
project those fields into CG's typed refusal representation, not parse text.

A successfully resolved closure with zero enums SHALL use a private empty
`EnumMemberIndex`; emptiness is a result of complete reconstruction, never a
fallback after absent capability, stopped traversal or failed lookup. This
includes genuine zero-enum nominal closures only when their required owner
keys have been obtained. A reached enum SHALL construct every admitted case,
including unused cases, from that same immutable genuine capability.

Every prepared wrapper SHALL retain private expected package, item and
descriptor binding, its descriptors, admitted environment and index, and its
optional context plus whether its recipe requires nominal identity. The
oracle SHALL refuse a wrong private binding, a mismatched retained `Some`,
or missing context for a nominal recipe as `Outcome::Refused(Refusal::CheckedInvariant { cause: CheckedInvariantCause::GeneratedDescriptorReconstructionFailed })` before
any meter charge. For a valid context-free recipe, retained `None` is not
such a fault. The oracle SHALL check both expected comparison types against
its prepared environment and call QSV `check_equality` with that same private
index before every evaluation. A private environment-only fault fixture
retains the correct optional capability/index and creates no public unchecked
constructor. AC-8 and AC-9 retain all their environment and charge-stop
controls. A raw caller-created index is not an alternative ABI. Preparation
and any source compilation remain outside metered execution; generated
oracles still execute the implementation under test, not a replay substitute.

Standalone `None` authenticates neither source meaning nor native semantic
agreement. It changes no strict IR admission requirement or caller-declared
operation limitation. It SHALL NOT bypass native
`OriginalCompositeEqContext::request` source/lock/package checks, exact full
recompiled-package equality, typed admission failures, selected occurrence/
operator checks or import guard. A successful native request always retains
and supplies its genuine admitted capability. Ordinary scalar proof manifests
and bodies acquire no replay compilation/context leg.

### Direct Integer operand and target identity

When a directly selected operand source or caller conversion-target ID names
canonical `scalar_type` / `integer`, the generator SHALL reconstruct unbounded
`Integer`, even when another parameter or context root has an `integer_range`
over that same canonical base. When that selected ID names `integer_range`,
the generator SHALL use that domain's exact own interval. A package-wide
base-to-bound index, an unrelated sibling range or a union of ranges is not
a direct operand's declared bound. This follows the parameter type identity
of Contract IR FR-038 and the distinct Int/Integer conversion rows of
[QSpec FR-149](ix://agent-ix/quire-specification/FR-149). It requires no new
public descriptor field and changes no type-resolution charge or
equality-conversion rule.

This direct-root rule does not rewrite AC-16's existing numeric member/base
equivalence or its precise regression. Genuine record/tuple member association
is separate unresolved scope: an unqualified canonical base key alone does
not identify a lexical owner or distinguish a genuinely associated member
bound from another parameter's range. Do not invent that association or claim
this operand-only clarification resolves it. The genuine record/tuple key
capability gap also remains. Existing specified member behavior and tests
remain required pending explicit owning resolution.

### Admitted Union reconstruction

When an equality item's closure reaches an admitted Union, the generator and
emitted environment constructor SHALL look it up by its original wire node
through `AdmittedContext::composite_declaration`, verify its name and Union
form, and preserve its declared member and payload-position order throughout
the nested declaration closure. `CompositeDeclaration` and
`ValueType::Composite` SHALL use the admitted `key()`; after constructing the
complete environment, each Union SHALL be sealed through
`seal_union_verified(key(), node(), bindings)` with clones of the authoritative
`AdmittedUnionMember::member()` bindings. The distinct node/key roles and
same-shaped declaration identities are owned by
[QSL FR-396](ix://agent-ix/quire-spec-language/FR-396), AC-6 through AC-9;
CG SHALL consume those identities without constructing substitutes. Missing or
wrong context, Unknown/Foreign/WrongKind lookup, name/form disagreement and
seal failure SHALL retain their typed causes, publish no successful prepared
wrapper and admit no equality-meter charge. Per-item failures SHALL leave a
healthy sibling unchanged; the existing whole-request context-mismatch guard
and charged resolution precedence remain in force. This consumer amendment is
PLANNED under AC-44; the existing Quantity refusals in AC-18 and AC-38 remain.

### Admitted unit-table metadata retention

When generation-time environment construction or emitted environment preparation
receives `Some(context)` after the existing setting/accounting and
original-package context guards succeed, CG SHALL attach a clone of that
context's complete authoritative `unit_table()` to the constructed
`TypeEnvironment`. The table and its unit identities are owned by
[QSL FR-398](ix://agent-ix/quire-spec-language/FR-398); CG SHALL consume that
original table without rebuilding it, deriving `UnitId` or `NodeKey`, or
substituting another package's table. Declared but unused admitted units remain
part of the retained table, even when absent from the emitted graph.

For valid context-free `None`, CG SHALL preserve the existing construction
behavior. Metadata attachment SHALL preserve the existing guard and refusal
precedence, the direct and nested Quantity `Unsupported` behavior of AC-18 and
AC-38, and unaffected sibling results. AC-45 is metadata retention only: it
adds no positive Quantity equality or conversion acceptance. Its planned host
checks distinguish in-process table retention from inspection of the emitted
attachment recipe; neither establishes execution of the emitted crate or Kani
acceptance.

### Existing equality behavior

- When generation begins, the generator shall consume each requested node's
  existing complete-lowering accounting in the admitted ContractPackage,
  with its full request-position mapping, and select exactly one generated
  or refused disposition per bound item; it shall not lower a second package.
- When a lowered node is a `binary` expression whose operand `semantic_type`s
  reconstruct to a declaration closure that `TypeEnvironment::new` admits, and
  whose descriptor `TypeEnvironment::check_equality` admits, the generator shall
  emit that item's environment constructor and oracle function.
- Each emitted oracle function shall call `TypeEnvironment::check_type` on each
  of its descriptor's two operand comparison types, then `check_equality` with
  the item's descriptor and its prepared genuine `EnumMemberIndex`, then `CheckedEquality::evaluate` on the caller's two
  values and `Meter`, returning its `Outcome<bool>` unchanged. It shall contain
  no `unwrap`, `expect`, `unwrap_unchecked`, `assert!`-family macro,
  `process::abort`, panic macro (`panic!`, `unreachable!`, `todo!`,
  `unimplemented!`), index or arithmetic that can panic: an `IllTyped` from
  either `check_type` or `check_equality` becomes a typed
  `Outcome::Refused(Refusal::CheckedInvariant { cause })`, retaining the original
  `IllTypedCause` in `GeneratedTypeCheckRejected` or `GeneratedEqualityCheckRejected`
  respectively, before any charge.
- If QSV `TypeEnvironment::new` admission refuses the item's declaration closure — duplicate
  key, duplicate member, unknown declaration, an ill-typed member, or either
  recursion pass — then the generator shall refuse the item with that
  `DeclarationCause` and emit no code for it, without changing any other item's
  output. QSV environment resource failures retain their typed limit/allocation
  cause and are never converted to `InvalidDeclaration`. A duplicate-field
  source control is rejected by the owning QSL declaration admission before a
  genuine context exists; it is not a public CG malformed-declaration input.
  Preserve that typed source refusal separately from private CG
  duplicate-member declaration defenses and their exact cause/sibling checks.
  Those defenses do not establish public generation-time reachability. This
  stage distinction does not reclassify the other declaration or recursion
  controls above.
- FR-021's planned emitted function environment is a separate construction
  path: it shall consume the selected checked closure owner's actual nominal
  declarations through the owner facade and map a genuine construction
  rejection to FR-042's `GeneratedEnvironmentRejected`. This does not change
  this equality item's generation-time `EnvironmentError::Declaration`
  contract, and is blocked by QSL-1105 until the facade exposes record/tuple
  members.
- The generator shall reconstruct each item's operand types with a separate,
  caller-selected type-resolution work limit (default 65,536 units). Entering the root type node or
  following one member, option-payload, or collection-element reference or a
  bounded-domain `semantic_type` edge to a type node consumes one unit; the
  counter is shared by that item's two operands
  and conversion targets, and resets for the next item. A repeated reference
  consumes a new unit even when its node was previously resolved or memoized;
  an in-progress record back-edge also consumes its reference-entry unit before
  closing to the key. Before an entry that would exceed the effective limit,
  it shall refuse only that item as
  `CompositeEqualityRefusal::TypeResolutionWorkExhausted { limit,
  consumed }`, with `limit` the effective setting and `consumed` the first
  denied entry; the refusal also names its stable setting name, and emits no
  symbols. This budget is independent of
  `COMPOSITE_EQUALITY_LOWERING_WORK_LIMIT`, which governs Contract IR lowering;
  neither is a nesting-depth limit.
- The type-resolution work limit shall be a `u64` in the range `0..u64::MAX`.
  If a caller supplies `u64::MAX`, the generator shall reject the request as
  `InvalidTypeResolutionWorkLimit` before lowering or charging any item: a
  `u64` refusal cannot encode the first denied count after that setting.
  For every admitted setting, the first denied count is representable.
- Type resolution shall use an explicit charged walk whose native call-stack
  use does not grow with input size or nesting depth. Its working storage shall
  grow by at most a constant per charged entry. Rendering the reconstructed
  closure and releasing CG-owned work frames shall also avoid native recursion
  proportional to the input. An edge
  back to a record or tuple declaration already in progress shall close as
  that declaration's `NodeKey`, including a record field reached through an
  `option` payload or `sequence` element. An edge back to an unclosed `option`
  or collection type shall instead refuse only the item as
  `CompositeEqualityRefusal::TypeResolutionCycle { type_node_id }`, naming the
  repeated node. The generator shall report that cycle at the repeated entry
  after charging the entry and before following any child. For a long acyclic
  chain, the generator shall report a work refusal only at the first denied
  entry, without a panic or process abort.
- The generator shall render the reconstructed closure as a flat sequence of
  bounded-size declarations and temporaries, not as a Rust constructor tree
  nested once per type entry. The total generated Rust source byte count shall
  be charged against the effective caller-selected source limit before bytes
  are appended; at the first denied byte, the whole request shall return its
  existing `SourceTooLarge` error with the effective limit and needed byte
  count and the `cg.equality.source_bytes` setting, and publish no partial
  artifact. Its default preserves the existing
  1,048,576-byte refusal. A raised limit shall admit a larger source when each
  artifact fits the publication byte limits; when source exceeds one artifact,
  the generator shall partition it into deterministic instruction-order
  modules so no emitted artifact exceeds its publication limit.
- For the QSpec List record, the generator shall read `next` through its
  `binding(next, aggregate([binding(optional, reference Option<List>)]))`
  structure, follow the option node's sole payload reference to List, and emit
  `FieldDeclaration` with the genuine List `NodeKey` and `Presence::Optional`.
  At the private parser/type-resolution defense seam, a missing or differently
  named nested binding, more than one nested member, or a nested reference
  that does not name an option node shall retain the exact malformed-item
  refusal, no symbol and unaffected healthy sibling, rather than treating the
  field as required. These inconsistent internal shapes are not claimed as
  successful source admission or public CG malformed-branch inputs. Any
  separately exercised malformed source/wire control retains its actual
  owning admission refusal before CG, with no genuine successful context or
  admitted package for the refused control; it does not replace the precise
  private defense or weaken the genuine valid List/Tree path.
- For the QSpec Tree record, the generator shall follow `kids`' direct reference
  to `collection_bounds`, use that bounded-domain node's `semantic_type` to
  find `Sequence<Tree>`, read its one element reference back to Tree, and form
  `Sequence(Tree, CardinalityBound(0, 3))` from the domain's named `min` and
  `max` bindings. Missing, duplicate, or ill-typed bounds and a domain whose
  `semantic_type` is not a sequence shall refuse the item with a typed cause;
  neither shall be read as an unbounded sequence.
- When a member's type node is a scalar `bounded_domain` node, the generator shall
  read the member as the type of that node's base `scalar_type`, bounded
  by that node's own `binding` members and by no sibling bound over the same base.
  A `collection_bounds` node whose `semantic_type` is a `sequence` node instead
  reads as a sequence of that node's sole referenced element type, bounded by
  the domain node's own `min` and `max` bindings.
- If a member's type node is a `bounded_domain` node whose base is neither a
  `scalar_type` nor a `sequence` with `collection_bounds`, or whose base scalar
  reads no bound form (boolean or enum),
  then the generator shall refuse the item as unsupported, naming the bound
  node; if the node's form is not the one its base reads (`integer_range` over
  `integer`, `rational_range` over `rational`, `decimal_range` over `decimal`,
  `text_bounds` over `text`, `float_rounding` over `float32` or `float64`), then
  it shall refuse the item as missing that form, naming the bound node. Neither
  is read as an unbounded type. A `float_rounding` member reads as the float, so
  the equality is refused as an IEEE-bearing operand (FR-018-AC-6) by the next
  clause.
- If `check_equality` refuses the descriptor — a `convert<T>` operand outside
  `admits_equality_conversion`, distinct text profiles, distinct enum
  declarations, incompatible dimensions, distinct units, no common type, or an
  operand type that bears an IEEE value at any depth — then the generator shall
  refuse the item with that `IllTypedCause` and emit no code for it.
- FR-039 package accounting precedes equality classification. A requested model,
  function, state or temporal root outside the equality lowering profile retains
  its exact `Unsupported` record and source occurrences as `PackageAccounting`,
  with no oracle. A `reference` composite rejected by Contract IR's strict
  reader cannot reach this generator. For a lowered `call` expression, the
  generator shall retain its quire-contract-runtime#34 blocker.
- When a directly requested root is `temporal`/`formula`, `temporal`/`fairness`
  or `expression`/`case`, the generator shall refuse it as
  `CompositeEqualityRefusal::Unsupported`. The claim retains its requested
  node id, and the refusal retains IR lowering's first unsupported reachable
  node and tag, or the `case` root and `expression` tag when that root lowers.
  A temporal clause remains blocked even when its closure reaches a formula
  or fairness node first.
- If a node is unlowered, invalid, over its work limit, of a form other than
  `binary`, or disagrees with its descriptor's arity or operand types, then the
  generator shall refuse the item with a typed reason.
- For an admitted FR-330 package carrying a `failed` feature-accounting record,
  the generator shall retain that exact typed record and source occurrences as
  `PackageAccounting`, without classifying a byte limit as work exhaustion.
  Contract IR FR-038-AC-95 returns `failed`/`bytes` for every requested root
  and no package when its canonical bytes exceed the ceiling. With no admitted
  package, FR-039 refuses the whole call before CG can produce any item claim or
  artifact; the producer's `limit` and `consumed` remain authoritative.
- Each operand of a `binary` node is a `reference` to the node that denotes it, as a
  checked package keys every operand as its own node. The generator shall read an
  operand's type as that node's `semantic_type`, except where the node is an
  `expression` whose body is an `application` of operator `convert`: that operand is a
  conversion, and the generator shall read the type of the conversion's first argument,
  following nested conversions to the first node that is not one. That type is compared
  with the descriptor's `source_type`. The conversion's own `result_type` is not
  compared with the descriptor's conversion target: whether the descriptor's
  conversion is admitted is `check_equality`'s verdict on the descriptor, not the
  body's. An operand that is not a `reference` has no type to read and disagrees with
  its descriptor.
- If one node id appears more than once in the request under one descriptor, then
  the generator shall refuse every copy. One node id under two descriptors is not
  a duplicate: the operation law is caller-declared and V2 does not carry it, so
  two descriptors over one node are two distinct items and each receives its own
  disposition and symbol.
- The generator shall order output by the item's **descriptor key** so that equal
  requests in any order produce identical bytes. Node id alone is not a total
  order, because one node id carries one item per descriptor. The descriptor key
  is the sequence: the expression node's id, then the operator's rank (`Equal`
  before `NotEqual`), then the V2 node ids of the left operand's source type and
  conversion target, then the right's, an absent conversion target ranking before
  every present one. Every node id in the key is compared in node-id order — the
  same rule this requirement already uses for node ids, and the only
  total order available: the runtime's `ValueType` derives `Clone`, `Debug`, `Eq`
  and `PartialEq` and no `Ord`, `EqualityOperator` derives no `Ord`, and the
  runtime publishes no canonical encoding of a `ValueType`, while `NodeKey`
  derives `Ord`.
- The generator shall build each symbol from its operator's readable stem.
- The generator shall use a stem that one item holds bare.
- The generator shall suffix items that share a stem with `_{n}`, numbered from 1
  in ascending descriptor-key order.
- The composite-equality generator, `src/oracle/equality/mod.rs`, shall contain no
  panic token in its non-test code: `unwrap`, `expect`, `unwrap_unchecked`,
  `unwrap_err`, `expect_err`, `unwrap_err_unchecked`, `panic_any` or `resume_unwind`
  however written, the macros `panic`, `unreachable`, `todo`, `unimplemented`, `assert`,
  `assert_eq`, `assert_ne`, `debug_assert`, `debug_assert_eq` or `debug_assert_ne`, or
  `abort` anywhere but as a method call, so `process::abort` is a panic token
  (FR-018-AC-19).
- When emitted code reconstructs a literal or a bound, it shall do so only inside
  helpers returning `Result<_, ReconstructionError>`.
- When a reconstruction helper's runtime constructor or parse fails, the helper shall
  return exactly the `ReconstructionError` variant that names it and nothing else,
  never recovering, widening the type or naming another cause.
- When a reconstruction fails, the emitted environment constructor shall return
  `EnvironmentError::Reconstruction`; the oracle is not called with that failed preparation.
- When an oracle receives a prepared descriptor with a wrong binding, expected package
  identity or context requirement, or an admitted context with a wrong package identity,
  it shall return `Outcome::Refused(Refusal::CheckedInvariant { cause: CheckedInvariantCause::GeneratedDescriptorReconstructionFailed })`
  before any meter charge.
- If `render_value_type` is given `ValueType::Quantity` or `ValueType::Reference`,
  then it shall return `Err(RenderError::UnsupportedValueType { family })`, `family`
  being `"quantity"` or `"reference"`. `RenderError` is a private type of
  `src/oracle/equality/mod.rs`, not public API. It has a second variant,
  `Generation(OracleGenerationError)`, which carries the whole-call
  `UnknownRuntimeVariant` that `render_value_type`, `collection_kind_path`,
  `rounding_path` and `profile_path` return for a runtime enum variant this
  generator does not know.
- When the generator receives `RenderError::UnsupportedValueType` while rendering an
  item, it shall refuse that item as `CompositeEqualityRefusal::Unsupported` with
  `node_tag` equal to the error's `family` and `unsupported_node_id` equal to the
  item's expression node id, emit no code for it, and leave its siblings unchanged.
  Rendering takes a `ValueType`, which carries no node id, and runs both for an
  operand's source and target types and inside `render_composite_declaration`, so
  the expression node is the one node every call site knows.
- When the generator receives `RenderError::Generation`, it shall fail the whole call
  with the carried `OracleGenerationError`, as it does for `UnknownRuntimeVariant`
  today.
- If the generated source exceeds its size ceiling, then the generator shall
  return a typed error and no partial output.
- Planned (IR-241, IR-264): the generator shall record, in each generated item's claim-map entry,
  the declaration closure with each declaration's key, form, members in declaration order (name,
  presence and type) and each leaf's family and declared bound, read from the same
  reconstruction the item's environment constructor is emitted from, so that
  [FR-015](../../kani/functional/FR-015-bounded-kani-obligations.md)'s shadow and this oracle read
  one closure (FR-018-AC-21).
- Planned (IR-241, IR-264): the generator shall emit, for an item whose leaves are Boolean or
  bounded integers, an oracle that completes every pair of operand values in the item's
  refinement domain (FR-028-AC-16) with the FR-149 verdict and the FR-149 charge schedule under an
  unlimited `Meter`, and never returns `Refused` or `Incomplete` for such a pair (FR-018-AC-22).
  That is the property the shadow of FR-015-AC-69 leaves out of its model and the refinement
  obligation of FR-028-AC-15 checks. It is stated of the oracle function, so it holds whichever
  evaluator the function calls; over the whole declared domain it is the refinement class's claim
  (exhaustive or sampled), not a universal one made here.
- Planned (IR-241, IR-264): the generator shall check each claim-map closure against an independent
  read of the checked package's declared types, taken through Contract IR's reader and not through
  the generator's reconstruction (FR-018-AC-23).

The runtime's `DeclarationCause` has no cause for an empty interval, a zero
denominator or an empty cardinality bound, which is why the emitted constructor
does not report a failed reconstruction as `InvalidDeclaration`. The public
`OracleGenerationError` is shared by the scalar, function and equality
generators and matched exhaustively by its consumers, and no existing variant
describes a known but unsupported `ValueType` (`UnknownRuntimeVariant` would
misreport it as an unknown one), so the render failure uses the private
`RenderError` and reaches callers only as the per-item refusal above. No request
reaches it today, so the mapping is asserted where reachable.

## Out of Scope

- Function application oracles, which
  [FR-021](./FR-021-function-application-oracles.md) generates through its own
  entry point.
- Model graph, identity and reachability oracles, which no requirement owns.
- Temporal and protocol oracles.
- `Refusal::ForeignReference`. It is the runtime's one substantive equality
  refusal — a reference pair whose universes differ, refused at plan time — and
  because the reference exclusion above is total, no operand this requirement
  admits can reach it. It is therefore named in no criterion and exercised by no
  vector, and the only run-time `Outcome::Refused` a generated oracle can produce
  is `Refusal::CheckedInvariant` (AC-8). That is a consequence of the exclusion,
  not an omission.
- Composite and collection *construction* oracles. This requirement generates the
  equality relation over completed operands; `construct_collection`,
  `form_collection`, `evaluate_record` and `evaluate_tuple` are the runtime's
  FR-008 constructors and are called by the corpus, not emitted.
