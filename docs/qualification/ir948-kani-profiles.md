# IR-948 V2 precondition, postcondition and invariant profiles under installed Kani

This file is the durable record behind the executed part of FR-015-AC-126 and FR-015-AC-129. The tests are in
`tests/it/kani_obligations_v2_profiles.rs`.

## Fixture

The `test/bank` domain package declares `Account.balance: Int[0, 100]` and `withdraw(amount: Int[0, 100])` whose frame
modifies `balance`. The QSL unit authors `pre CanAfford { amount <= self.balance }` and
`invariant NonNegative at current { self.balance >= 0 }` and `post Debited { self.balance <= pre(self.balance) - amount and self.balance >= pre(self.balance) - amount }`. Each harness is generated by
`negotiate_kani_native_obligations` from the package QSL emits, at unwind 8, and run through `execute_kani_obligation`
(the FR-017-AC-63 two-phase run) with a test-side `cgroup-memory.peak` source. The invariant counterexample is decoded and
replayed with `StateClauseReplay::new_invariant` and QSL's `replay_state_clause`.

## Run conditions

The five installed tests assert the identity ceiling is 24 GiB and that the environment supplied a peak below it. The
cgroup cap itself is the caller's: `make kani` runs the lane without a `systemd-run` scope (the same gap as the IR-917
controls), so the cumulative `memory.peak` it would read is the session's, and the figures above are from the hand
command shown.

## Postcondition harness

The postcondition harness draws the `balance` pre-state and `amount`, evaluates `CanAfford` through its own native oracle,
embedded in the nested module `requires_0`, on those draws and assumes it `Completed(true)`, copies the pre-state into
`post_balance_current`, calls `crate::subject::check(&mut post_balance_current, parameter_amount_current)`, asserts the
produced balance in `[0, 100]`, computes the independent native expectation over the pre-state copy and the produced state,
runs the clause oracle (pre-state copy for `pre(...)`, produced value for the bare read) and its two arithmetic subterm
probes, and asserts the oracle agrees with the expectation and that the clause holds. The sibling is assumed through its
oracle and not through a second native rendering, so no unchecked rendering of the precondition shapes the assumed input
space. The default-lane tests pin the order and wiring
(`the_state_reading_postcondition_yields_a_harness_with_requires_and_a_mut_subject`), the refusals of an arithmetic sibling
and the unreachable `pre(...)` sibling, and the draw and decode order of a mixed precondition.

The mutant's witness-phase run peaks at 21.96 GB, 85% of the 24 GiB cap (25.77 GB) with 3.8 GB of headroom. The earlier
run of the same mutant without the embedded sibling oracle peaked at 19.7 GB (240 s); embedding the oracle added about
2.2 GB. A further change to the harness, subject or package can push this run into `MemoryExhausted`, which is
`Inconclusive` and not a pass.

The native evaluation of the mutant witness runs the same compiled subject (one macro defines it for the test and for
the Kani source) over the decoded pre-state and amount, then evaluates the postcondition as the test's native reading of
the clause text (`post == pre - amount`, the conjunction of its two comparisons).

## Not established

- Postcondition on the specified text: one blocker with an owner. QSL refuses the specified text
  `self.balance = pre(self.balance) - amount` with `undefined_expression (unproved-range)` (QSL-1901, which blocks IR-948
  for the postcondition member only); the guarded, `and`-guarded, reordered, sum and difference forms are refused the same
  way, and the conjunction `self.balance <= pre(self.balance) - amount and self.balance >= pre(self.balance) - amount` is
  accepted. The V2 clause generator renders the state-reading postcondition (IR-948 slice 2b). The default-lane test
  `the_postcondition_renders_and_the_specified_equality_text_is_blocked_by_qsl` pins the QSL refusal so a fix flags the
  stale PARTIAL. FR-015-AC-129 requires the `=` text; the conjunction is the interim fixture text and earns no credit.
- The postcondition mutant is decoded and its postcondition evaluated natively, not replayed through QSL's
  `replay_state_clause`, which has no scalar V2 postcondition envelope.
- Frame: the profile package grants its only field, so a frame harness has nothing to forbid; the frame member is delegated
  to FR-015-AC-31 and FR-015-AC-80 (PLANNED, owner IR-624) over the two-field twin and is not part of FR-015-AC-126.
- The four-kind run over one package has therefore not been executed as one run: the precondition, postcondition (interim text) and invariant members have.
