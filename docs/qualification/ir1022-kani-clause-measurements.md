# IR-1022 installed-Kani measurements of the native V2 clause harness

This file is the durable record behind FR-015-AC-147 and FR-015-AC-148. It states what was run,
what it was run on, what came back, and what was not exercised.

## What was measured

- Harness: the sealed V2 clause harness CG generates through the native route
  (`negotiate_kani_native_obligations`) for the `test:state-frame-twin` fixture clause
  `result = (amount < 1000 implies amount + 1 <= 1000)` over `amount: Int[0, 1000]` with a
  declared Boolean operation result (`Twin::with_bounded_amount_implication`), unwind 3. It is the
  generated source of CG at the head of PR #800 before the fix round; the fix round changes no
  generator source and no harness text.
- Subject: NOT generated by the pipeline. The generated crate was copied to a scratch directory and
  a hand-written `pub mod request { pub fn unrelated(amount: i64) -> bool { .. } }` was appended,
  because the harness calls the subject at `request::unrelated`.
  - healthy subject: `!(amount < 1000) || (amount + 1 <= 1000)`; it does NOT call
    `quire_contract_runtime::operators::implies_short_circuit`.
  - mutant 1 subject: `!(amount < 1000) || (amount + 2 <= 1000)`; does not call the helper either.
  - helper control and helper mutant subject:
    `quire_contract_runtime::operators::implies_short_circuit(amount < 1000, || amount + 1 <= 1000)`.
- Dependencies: quire-exact `main` at the commit CG's `Cargo.lock` records (it includes the
  `evaluate_native_boolean_equality` kernel, FR-397-AC-5, and the u64-native schedule); the lock
  was seeded from CG's own. The helper mutant used an isolated copy of quire-contract-runtime wired
  by a Cargo `[patch]` path, with the body of `implies_short_circuit` replaced by
  `let _ = (antecedent, consequent); R::from(false)`.
- Mutant 2 (oracle): in the embedded oracle `scalar_8` the call
  `nx::evaluate_native_integer_ordering(nx::OrderingOperator::LessOrEqual, ..)` was changed to
  `OrderingOperator::Less`; the subject stayed healthy.

## How it was run

Raw `cargo kani` (Kani 0.68.0, rustc nightly-2026-08-21) in the scratch crate, one run at a time
under the shared cargo slot lock, inside `systemd-run --user --scope -p MemoryMax=24G
-p MemorySwapMax=0` (the 16 GiB rule was lifted by the planner and the owner for these
measurements) with a 1800 s cap:

    cargo kani -Z function-contracts --harness <module>::prove_clause --exact --unwind 3 \
        --solver cadical --output-format regular

Mutant runs add `-Z concrete-playback --concrete-playback print`. Peak memory is the cgroup
`memory.peak` of the scope (not process RSS), sampled every 2 s; wall time is the whole
`cargo kani` invocation including compilation.

- mutant 1: assertion "the produced V2 Boolean result agrees with the independent checked

- mutant 2: assertion "the V2 postcondition holds for the produced result"; playback `999`.
- helper mutant: assertion "the produced V2 Boolean result agrees with the independent checked
  condition"; playback `1000`.
- Mutants 1 and 2 each print a second playback with `amount_current = 1000` labelled
  `Check for cover: "the V2 result postcondition reaches its admitted domain"`; that is the witness
  of the satisfied cover, not a counterexample.
- The helper mutant prints one playback only (`1000`), and that is the counterexample of the failed
  assertion; its cover is unreachable (the helper always returns false), so it has no cover witness.

Earlier history on the same harness shape: with the earlier bignum Boolean equality schedule the

## What this does not establish

- Not CG's runner: no `run_kani`-style launch, no FR-017-AC-63 two-phase run (proof phase plus
  witness phase), no `WitnessDisagreed` classification, no identity record.
- The subject is hand-written beside the generated crate; the crate was not regenerated from QSL
  source and the subject was not compiled by the pipeline.
- The kernel `+` mutants of FR-015-AC-41 (`left + right + 1`, `left`) and the deterministic
  `amount_current = 999` sealed-artifact playback were not run.
- The 16 GiB cap itself was not exercised; the measured peaks (2.77 GB healthy, at most 11.8 GB
  for mutants) are the only fit information.
