# SR-1372: CG PR 256 spec review (base)

## Summary

Ticket: IR-465. The checklist was run over the diff only, and every QSL claim was measured
against QSL `origin/main` at 7c2cb303, the same commit the author names.

What is true against merged QSL:

- `qsl-replay/src/proof_result.rs` has `TerminalValue` with seven variants (`Proved { success_checks:
  u32 }`, `Tested`, `Refuted`, `Declined`, `Unsupported`, `Incomplete`, `Failed`).
  `InconclusiveCause` has only `KaniVacuousProof`. Nothing has `NonZero`.
- `ReplayResult`, `WitnessArmResult`, `WitnessSettlement::{ReproducedWithEvaluatedWitness,
  Inconclusive}` and `DisagreementCause::{Verdicts, NoValue, Witness}` exist (`result.rs`).
- `ReplayRefusal::Fault` and `ReplayRefusal::Admission(AdmissionFailure::Fault(_))` exist. The
  latter's `code()` is `runtime_invariant` (`execute.rs:255`). `CallSiteRefusal::Fault` exists
  (`call_site.rs:238`). `ReplayPackageError::CallSite` and `FrameReplayError::CallSite` are CG
  types (`src/replay/function.rs:281`, `src/replay/frame.rs:56`), so "wrapped in" is correct.
- ADR-013 C-09 (line 668 and the C-09 row at 986) names `replay_parity` and `replay_refused`, and
  says `InconclusiveCause` "gains" them and `TerminalValue` "gains" an `Inconclusive` variant. That
  is planned text in a merged ADR, and the code does not have it. The PR says so honestly
  ("not yet in QSL's `main`").
- Merged C-09 keeps a vacuous proof as `Proved { success_checks: 0 }` and says C-09 produces
  `Inconclusive` "only with `ReplayParity` or `ReplayRefused`, never with `KaniVacuousProof`". So
  FR-029's vacuous and cover-unsatisfied rows staying `Proved{0}` agree with merged QSL.
- Not merged: `TerminalValue::Inconclusive`, `InconclusiveCause::{ReplayParity, ReplayRefused}`,
  `NonZero` `Proved`, and any replay-outcome input type (CG's AD-004 step 5 defines the input type
  itself, in `kani/terminal.rs`).

What the author got wrong: "QSL-352 refusal codes for ReplayRefused" are listed as not merged.
`CallSiteRefusal::code()` and `DependencyInputRefusal::code()` are on QSL main. They came in
05032003 (QSL-614, #595), which is an ancestor of CG's own locked `qsl-replay` (934e26fb). See
FND-002. Merged QSL FR-121 also gives a settlement rule for those refusals, and the PR's rule
contradicts it. See FND-001.

Coverage: `quire coverage --strict --scope .` gives 66 unbacked rows at the base and 76 at the
head. A sorted diff of the two outputs shows exactly ten added rows: FR-029-AC-8 to AC-13 and
FR-030-AC-9 to AC-12, each "has no backing symbol [verification]". No other row changed. The rise
is the honest result of ten new planned criteria, and the merged precedent #250 did the same
(66 to 72 for planned NFR-005 criteria). #252 stayed at 66, and #255 (open) claims 66 because it
adds NFR rows. The baseline note should read: "strict unbacked 76 (66 plus the ten planned
IR-465 criteria FR-029-AC-8..13 and FR-030-AC-9..12); it returns to 66 when the IR-465 code lands
with its tagged tests."

Ids: `git log -S` on main finds no FR-029-AC-8..13 or FR-030-AC-9..12. FR-029-AC-7 appears only in
the #186 squash message ("delete the source-scan criterion FR-029-AC-7"), so skipping it is right
and no id is reissued.

## Verdict

**Not mergeable** until FND-001 and FND-002 are fixed. FND-001 is the blocker: the PR's
setup-refusal rule contradicts merged QSL FR-121, which needs an owner ruling or a QSL amendment,
and the spec must say which. The other findings are wording and honesty fixes. FR-029-AC-1's
amendment ("`falsified` with a reproduced replay maps to `Refuted`"), the fault walk, the closed-set
rule and the removal of `proof_category` are consistent with merged C-09 and AD-003 E-9.
