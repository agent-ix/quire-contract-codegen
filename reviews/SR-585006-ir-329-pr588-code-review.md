## Summary

Ticket: IR-329. Independent static review of draft CG PR #588, exact head
`23f9a049ed722d6366f4893e6d02577c6131be4c`, against merge-base
`1d5e8e95fc3ee38ded6bf92b4cf19f3769b1af81` (origin/main was
`29a6c5f9215da335143e844d004d06b59d371c19`). The single commit moves the symbolic collection
proof template from `collection.rs` into `render.rs` behind a new `HarnessSpec::new_collection`
constructor and an optional `CollectionSpec` on `HarnessSpec` (AD-004 step 4h), and adds

clippy and no tests. The two high findings come from tracing the existing guard tests'
source-scanning logic by hand against the new tree, not from running them. The PR's GitHub checks
on this head are only `cla`, `guard`, `publish-status` and `language-boundary`. No Cargo test lane
ran on the draft, so nothing executed has contradicted or confirmed these findings.

The rendered collection harness text is byte-identical to the pre-PR template. The module, harness
name, length and item bindings, element assumption, predicate, `all`/`any` call, assertion and cover
condition and message are the same strings. The artifact path is still
`src/generated/<module>.rs`. Harness identity, options and provenance are therefore unchanged.

## Verdict

FAIL (changes requested). The refactor keeps the generated bytes and identity. But it does not
update the two source-scanning guards that encode AD-004 step 4h: FR-015-AC-58's template census in
`tests/it/cover_last.rs` and L-2's collection import allowlist in `tests/it/layout.rs`. Static
tracing shows that `tc_025_no_proof_attribute_is_spelled_outside_what_the_inspection_drives` and
`l_2_every_import_follows_the_dependency_direction` fail at this head (FND-001, FND-002). Both
guards should move with the code, together with the AD-004 import-set text (FND-004). FND-003 is a
design defect against the rust-style rule "keep a fact in one place". With the current
representation, a collection spec's scalar-only fields are meaningless. An enum proof shape, or
collection-typed `Statement`s, would make that state unrepresentable. Correct: the typed
quantifier and element enums, `ExprText` validation of the cover, and the exhaustive predicate
match.
