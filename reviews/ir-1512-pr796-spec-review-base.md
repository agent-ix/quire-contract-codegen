## Summary

Ticket: IR-1512. PR #796 (spec only, head d9fe495c on origin/main c6efd974, which carries #795; branch spec/ir-1512-unread-field-snapshot) lifts the unread-field limit of the V2 invariant replay: FR-024-AC-58 is amended in place from refusal to snapshot completion, FR-024-AC-69 (completion) and FR-024-AC-70 (typed refusals) are added, `InvariantReplayInputs` gains the public member `unread_values`, TC-035 step 40 is rewritten and steps 48 and 49 added, interface-001 and the replay matrix rows are updated. Reviewed read-only against the code at origin/main: src/replay/state_clause/invariant.rs (`new_invariant`, `ensure_declaring_object`, `request_documents`), src/replay/state_clause.rs (`StateClauseReplayError`, the FR-029-AC-16 `ReplaySettlement` match, `SnapshotObject`, `populations`, `state_fields`, `replay_range`, `bind`), src/core/ir/clause.rs (`ClauseInput`), tests/it/state_clause_invariant_replay.rs (the AC-58 test at :297) and tests/state_frame_support/native_twin.rs (balance/audit twin, `with_field_ranges`, the Boolean, string, unbounded and wide-range `audit` fixtures), plus open PR #794 for id collisions. No cargo or build was run. `quire validate` over spec, plan and reviews (the make spec target) reports the same 6 warnings on the branch as on origin/main. `quire matrix` lists FR-024-AC-69 and FR-024-AC-70 as untagged and FR-024-AC-58 as tagged by tests/it/state_clause_invariant_replay.rs:297. Method: spec-review/base.

## Verdict

**CHANGES REQUIRED.** The design is implementable and sound against origin/main. `read_clause(..).inputs` gives the read set for the drawn/read refusal, so a supplied value can never reach a field the invariant evaluates, and the verdict does not depend on unread fields. `state_fields`/`replay_range` already read field ranges from the `model_object_fields` accessor. `bind` already gives `UndeclaredField`, `DuplicateField`, `MissingField` and `OutOfDomain` before `encode_document`. The payload's witness record is none and `declared_domains` is empty, so if the transcript is rendered from the playback bindings only, no supplied value reaches the witness or the packet. The `Int[-1, 1000]`/`Int[0, 1000]` twin can be built with `Twin::with_field_ranges` and `invariant_from`. `unread_values` touches only `InvariantReplayInputs`, so it has no interaction with FR-024-AC-71 to AC-75 (`StateClauseReplayInputs`, `FrameReplay`) or their error variants. Ids 69 and 70 collide with nothing; 67 and 68 were retired by #795. Not mergeable until FND-001 (an order clause no test can fail) and FND-002 to FND-004 are fixed.

| FND-005 | low | AC-70 reuses `OutOfDomain` for a supplied value of an unread field with no `i64` accessor range. `OutOfDomain` is documented, and displayed, as 'a playback value lies outside its field's declared integer range'. For a Boolean or string field there is no integer range at all. For an unbounded or wider-than-`i64` integer, the supplied value may lie inside the declared domain yet is reported as outside it. The refusal is reachable before any document is built (`replay_range` returns `None` for `ModelMemberNotI64Range`, and the validation precedes `encode_document`), and it settles as `Failed` like any of these variants. But the variant tells the caller the wrong thing. The generator already names this case `StateUnrangedReason::TypeNotRange` (src/kani/generate/frame.rs:943-946). Consider a distinct variant (for example `UnreadFieldUnranged{field}`), or say explicitly that `OutOfDomain` here means 'no i64 range'. | spec/replay/functional/FR-024-counterexample-envelope-intake.md:608 |
