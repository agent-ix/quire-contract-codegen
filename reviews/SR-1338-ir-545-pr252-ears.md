# SR-1338: CG PR 252 spec review (EARS conformance)

## Summary

Ticket: IR-545. The PR adds sentences to two existing EARS bullets:

- the unwanted-behaviour bullet "If one node id appears more than once ... then the generator
  shall refuse every copy";
- the ubiquitous bullet "The generator shall order claim-map entries by ...".

The AC-24 cell is direct assertions with no "shall", as this repo's ACs are written: one sentence
per example, each with a concrete input and output. Each lead clause is still EARS. The
definition sentence ("A function binding is the function name together with the argument
operands") is a definition, not a requirement, and is fine as written.

## Verdict

AC-24's form is conformant. One low finding: the new requirement sentences are not EARS.

## Findings

| ID | Severity | Summary | Refs |
| --- | --- | --- | --- |
| FND-001 | low | Two new sentences state behaviour descriptively instead of in EARS form. "When both names are absent from the request's declarations, each item gets its own claim-map entry refused as ..." is an event-driven requirement with no "the generator shall". "Items that tie on all of those keys ... are ordered by the function name in byte order" is a ubiquitous requirement with no "shall". Phrase them "When ..., the generator shall give each item its own claim-map entry ..." and "... the generator shall order them by the function name in byte order", matching the bullets they extend. | spec/oracle/functional/FR-021-function-application-oracles.md:235-237, 257-259 |
