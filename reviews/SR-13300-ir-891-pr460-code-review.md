# SR-13300: IR-891 PR 460 code review

## Summary

Ticket: IR-891 (item 1) and IR-897. PR agent-ix/quire-contract-codegen#460 at 619b84e2, two
commits on merge base 58f44780 (merged spec PR #458). The Rust lane is folded into this file.
The PR adds `core::provenance::with_rust_header`, which prepends the SPDX line, an
`@generated by quire-contract-codegen` line and one `// Subject:` line per subject, and calls it
from every generated-Rust emitter. Boolean oracles and the generic Kani renderer add the
generator line to their existing hand-written headers.

What the reviewer measured in a fresh worktree with its own target dir:

- Emitter inventory (grep of `Artifact::new` and `.rs` paths in `src/`): strategy harness,
  integer and enum strategies (`campaign.rs`), bound strategy, bound population, Boolean and
  bound oracles (`boolean_v1.rs`), exact-scalar package `src/lib.rs` (checked-package path and
  FR-330 contract path), composite-equality `src/lib.rs` and `src/composites_*.rs`,
  function package `src/lib.rs`, function schedule flat source, split root and
  `src/schedule_*.rs` parts, Kani generic render, V2 contract (`negotiate.rs`), V1 bundle,
  exact-scalar Kani, collection, state frame, and the three bounded corpus `.rs` files. Every
  production emitter calls the header. `routed/generate.rs:841` and `kani/test_support.rs` are
  empty test stand-ins. `render_scalar_reference` (scalar.rs:538) is `#[cfg(test)]`.
- `make fmt-check`, `make lint`, `make spec` and `git diff --check` pass.
- Full suite (`QSPEC_DIR` set): it 617 passed, 9 failed, 35 ignored. Seven failures are exactly
  IR-898's named set. The other two (`kani_obligations::cbmc_failure_terminal_value_reads_the_retained_cause`,
  `kani_obligations::tc_043_the_terminal_value_of_no_verdict_evidence_ignores_its_diagnostics`)
  and all 50 unit failures are in `kani::run`, `kani_terminal_private` and
  `kani_scalar_native_private`. They fail with `bwrap: setting up uid map: Permission denied`,
  which this host returns even outside the tool sandbox. The PR touches no file in those paths.
- No file under `src/kani/run`, the Kani gate or scalar-native changed. No hash, pin, revision
  or commit identity is invented, and no compatibility layer is added. Tags are `#[trace(...)]`.
- Output order is stable: subjects come from the sorted claim map, request order, or schedule
  instruction order.

Reviewer production mutants, each reverted after its run:

- Killed: removing the generator line from the Boolean oracle emitter (M1); removing the SPDX line
  from the generic Kani renderer used by exact-scalar harnesses (M2b); removing the `frame` node
  from the state-frame subjects (M3).
- **Survived:** passing `""` instead of the item node id to the equality extra module (M4,
  FND-002); dropping relation and domain from the bound population subject (M5, FND-005);
  dropping claim call nodes from the split schedule root header (M6, FND-004); not adding the
  header to the FR-330 contract exact-scalar `src/lib.rs` at all (M7, FND-003); dropping the
  function declaration nodes from the function package `src/lib.rs` header (M8, FND-004).

## Findings

| ID | Severity | Summary | Refs |
| --- | --- | --- | --- |
| FND-001 | medium | `with_rust_header` writes each subject raw after `// Subject: `. The state-frame emitter passes `scope.operation`, a free `text` literal read from the checked package. The model's conformance code treats control characters in a text literal as a valid boundary (`boundary:canonical.escape_controls`). An operation named `deposit\npub fn injected() {}` would end the comment and emit live Rust into the harness. The old frame header deliberately used `{:?}` for the same value, and frame.rs runs no `syn::parse_file` after the header. Fix: in `with_rust_header`, escape every subject (for example with `{subject:?}` or `escape_debug`) or reject control characters. Add a test with a newline in an operation name. | src/core/provenance.rs:11-13, src/kani/generate/frame.rs:1102-1110 |
| FND-002 | medium | The only header test for equality extra modules calls `SourceBuilder::add_composite_module("test", "test", ...)` directly. It never runs the call sites in `SourceBuilder::item` that pass `format!("{:?}", item.node_id)`. The one test that produces real extra modules (`deep_acyclic_closure_generates_flat_compilable_source_on_a_small_stack`) asserts no header, and the integration corpus produces none. Mutant M4 (subject replaced with `""`) passes every equality test. Fix: assert the header, including the claim node id, on the `src/composites_*.rs` artifacts in the deep-closure test or in an integration test whose composites exceed `MAX_DECLARATIONS_PER_FUNCTION`. | src/oracle/equality/mod.rs:1715-1738, src/oracle/equality/mod.rs:2764-2794 |

Mutant M7 removes the header from that emitter entirely, and all 16 `routed` tests still pass. No integration test asserts a header on routed output. Fix: call `assert_header` on the contract-path `src/lib.rs` in a routed test, with its generated claim node ids. | src/oracle/scalar/mod.rs:1213-1222, src/routed/contract_package_tests.rs:665 |

| FND-006 | medium | The NFR-002 tags are on the wrong test. `tc_029_ac10_bytes_are_deterministic_across_request_permutations` gained `TC-001`, `NFR-002-AC-1` and `NFR-002-AC-2` but has no header assertion. Fix: move the three ids to the test that asserts the header. | tests/it/composite_equality_generation.rs:1440-1442, tests/it/composite_equality_generation.rs:1560-1579 |
| FND-007 | medium | Header subject rules differ between the two layouts of the same schedule. Split `src/schedule_*.rs` parts name every instruction source node they render. The flat schedule source serializes the same instructions but names only function and claim call nodes. Whether a schedule's instruction nodes appear in a header therefore depends on byte size, not on what the file renders. NFR-002 Scope says a file rendering multiple subjects "names every source node or obligation it renders". Fix: use one rule for both layouts. Either name the instruction nodes in the flat source, or name only function and claim nodes in parts and state that rule in NFR-002. | src/oracle/function/mod.rs:674-683, src/oracle/function/mod.rs:761-771 |

## Verdict

**FAIL: not mergeable as is.** The mechanism is sound. One helper adds the header to every
production Rust emitter in NFR-002 Scope. Headers use only input-carried identities, output order
is stable, gates pass, and the only remaining failures are IR-898's seven plus host
user-namespace failures in untouched Kani runner code. Three emitter mutants are killed.
FND-001 is a real generated-source injection path through header text. FND-002 to FND-005 are
emitter paths that five reviewer mutants show the tests cannot catch. TC-001 says "do not
accept a single passing file as coverage for a family", and these paths are not covered.
FND-006 binds NFR-002 to a test that does not assert it. FND-007 and FND-008 are Scope
conformance questions to settle in code or in NFR-002.
