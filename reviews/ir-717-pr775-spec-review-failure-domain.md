## Summary

Ticket: IR-717. Spec-only PR #775 (head 141760f0, one commit): rewrites spec/decisions/ADR-005-original-guardian-gate-ownership.md from the #345 hold into a decision record (P1 safe alias exclusion FAILED, P2 conditional on P1, P3 finite bound FAILED for the Unix-stream transport, five UNRUN controls, six product options with none selected; FR-034/TC-049 unamended). Checked against: rustix 1.1.5 and 1.1.6 vendored source (src/thread/setns.rs unshare/unshare_unsafe, src/thread/prctl.rs seccomp/no_new_privs, src/net send_recv/msg.rs cmsg_space/sendmsg/recvmsg, sockopt.rs send buffer and peercred, socketpair.rs, io/read_write.rs pwritev2, backend io/types.rs ReadWriteFlags); nix 0.31.3 signal.rs; /usr/include and linux-headers-7.0.0-38 uapi (no O_CLOFORK; RWF_NOSIGNAL present); Cargo.toml/Cargo.lock (rustix 1.1.6 locked, nix via command-fds); src/lib.rs forbid(unsafe_code); src/kani/run/namespace.rs gate pipe and abort test; FR-034 Behavior and AC-38/54/83/87/94; TC-049; the #345 ADR on origin/main; IR-717 ticket acceptance and comments. quire validate and quire matrix pass. No Cargo, build, probe or kernel read was run.

## Verdict

PASS WITH LOWS. The custody walk-through correctly marks R (C copy) as an aliasable authority and the fork-child-writes-a-release-byte case. The adverse cases (fatal O, peer loss, partial rights, cancellation) are enumerated. All four findings are low: unverified kernel claims not marked as such, a missing safe seccomp-strict rejection, option 5 not citing existing PDEATHSIG/pidfd mechanisms, and an unverified SO_SNDBUF overhead claim.

| FND-001 | low | P1 evidence states that threads share one table, that fork copies it and that CLOEXEC does not act before exec as plain facts. 'Not grounded' lists only fork copying the table, not CLOEXEC-before-exec or the shared table. The absence of O_CLOFORK is grounded (no CLOFORK in /usr/include or linux-headers-7.0.0-38). The P3 text says the per-user in-flight counter is a 'statement from kernel source, not verified locally', but no kernel source is installed here (headers only). Put every unverified kernel statement in 'Not grounded' and say 'from kernel documentation/recollection' rather than 'from kernel source'. | spec/decisions/ADR-005-original-guardian-gate-ownership.md:65-69 |
| FND-002 | low | 'rustix 1.1.5 exposes no_new_privs setting but has no seccomp filter installation' omits that rustix also exposes safe thread::set_secure_computing_mode (PR_SET_SECCOMP, src/thread/prctl.rs:173) with SecureComputingMode::Strict. Strict mode would deny fork on the owner thread, but it allows only read/write/_exit/sigreturn (no close, sendmsg or poll) and is irreversible, so it cannot host the owner. The conclusion stands, but the rejection list should name strict mode and this reason, so a reviewer does not find it later as a missed safe route. | spec/decisions/ADR-005-original-guardian-gate-ownership.md:81-88 |
| FND-003 | low | Option 5 costs 'a new caller-death mechanism' for 'an identity not duplicated by fork'. The architecture already has non-descriptor caller-death signals: L arms PR_SET_PDEATHSIG on C's creating thread (FR-034 Behavior, 'Outer containment'), and C/L/O hold authenticated pidfds (rustix process::pidfd_open is safe in the enabled `process` feature). A pidfd that L or O holds on C does not alias into C's foreign forks. The option should say whether these existing mechanisms meet AC-83, rather than costing a new one. | spec/decisions/ADR-005-original-guardian-gate-ownership.md:165 |
| FND-004 | low | The 'Stream queued bytes' row says the send-buffer read-back caps payload but 'per-skb overhead not'. Linux charges AF_UNIX stream skb truesize, which includes skb overhead, against the sender's sk_sndbuf, with at most one message over the limit. If that holds on the supported kernel, SO_SNDBUF read-back bounds per-skb overhead too, up to one message. The opposite claim is not marked unverified. Mark the row unverified or derive it (kernel claim not verified here either way). | spec/decisions/ADR-005-original-guardian-gate-ownership.md:127-135 |
