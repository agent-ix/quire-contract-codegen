## Summary

Ticket: IR-304. Spec-only PR #768 (head de3d7ee1, base origin/main cf10ec78) rewrites FR-022's QSL requirement-record intake, adds the 'Per-occurrence requirement records' and 'Path conditions in the scalar harness' subsections, rewrites AC-26/27/28, adds AC-31..35 and an IR-304 Rationale, and updates the TC-033 procedure for slices (a)/(b) and the routed tests.md row. Verified against CG src/routed/generate.rs, src/kani/generate/{spec,scalar}.rs, src/kani/identity.rs, src/replay/scalar.rs, src/core/contract_package.rs, src/oracle/scalar/lower.rs; IR quire-contract-model c8dca8c (ContractOccurrenceKeyV1, result_context); QSL origin/main ffec6c72 (qsl-semantics check/claims.rs PathGuard/RequirementRecord/key_claims, qsl-route request.rs RequirementItem).

## Verdict

FAIL (one medium, two low). The interval rules are sound as stated for the parameter-on-left form. lt/le/gt/ge/eq intersect, `ne c` removes only an endpoint, and `holds=false` negates first, so `x > 5` with holds=false gives [0, 5]. Two-parameter comparisons narrow nothing, and every removed value falsifies an assumed guard. Statement::Assume placement is implementable: HarnessSpec refuses AssumeAfterCall (spec.rs:512-515), and Input supports Boolean. PathConditionUnsatisfiable is checked before the reachable-result check (scalar.rs:308-315 ResultUnreachable). The vacuity story holds: the `completed` cover is emitted after the call (scalar.rs:662-674), so an infeasible two-parameter guard gives CoverUnsatisfied, and AC-35's `x > y` control makes the case able to fail. The guard comparison operators are all catalogued (operator_catalog.rs). Defects: a non-lowered guard context root, the literal-on-left flip, and an empty Boolean interval.
