# SR-1291: CG PR 250 spec review

## Summary

Ticket: IR-543. PR: agent-ix/quire-contract-codegen#250 at 2995b8d. Base is current `main`
(f970692). The PR is spec only. This file holds the contradiction, trace, testability, ID-hygiene
and cross-PR checks. SR-1292 holds the EARS form checks. SR-1293 checks each AC against the code.

What I measured myself:

- The panic-site census. I ran `non_test_code` and `panic_tokens_in` of
  `tests/common/panic_scan.rs` over all 70 `.rs` files under `src/`, and then a variant that also
  blanks literals and keeps line numbers. The result is exactly fourteen production sites, the same
  fourteen the author lists: `oracle/function/mod.rs` 962, 1019, 1021 and 1060;
  `kani/generate/scalar.rs` 120, 183 and 199; `routed/capability.rs` 396;
  `evidence/bound_coverage.rs` 446 and 480; `kani/generate/corpus/bounded_kani_corpus.rs` 349 and
  610; `routed/generate.rs` 320 (`assert_eq!`); and `oracle/boolean_v1.rs` 922 (`debug_assert!`).
  `src/kani/test_support.rs` (six hits) is declared `#[cfg(test)] pub(crate) mod test_support;` at
  `src/kani/mod.rs:27-28`, so the exemption is correct.
- Removing literals drops only the `assert!` text the Kani generators emit (`frame.rs` 984 and
  1004, `scalar.rs` 400, the corpus file at 598) and the `"unwrap"` label at `boolean_v1.rs:799`.
  None of them is a generator panic.
- A search for panic-class APIs outside the token list (`process::exit`, `catch_unwind`, `RefCell`
  borrows, `copy_from_slice`, `split_at`, `chunks`, `pow`, `unsafe`) finds no unguarded site. The
  one `copy_from_slice` (`replay/witness.rs:178`) has a width check before it. The crate has
  `#![forbid(unsafe_code)]`.
- AC-1's token list is identical, byte for byte, to FR-014-AC-39's list (scripted comparison).
- ID hygiene. Neither `NFR-005` nor `TC-042` appears in any commit on any ref before 2995b8d
  (`git log --all -S`). NFR-003 was issued and later deleted, so skipping it is right under
  ADR-0056. TC-041 is the highest TC on main. Open PRs #222 and #209 add no NFR-005 or TC-042.
- `quire validate` over `spec/**`, `plan/**` and `reviews/**` gives output identical to main's (the
  same five module warnings) and exits 0. `quire coverage` goes from 228/337 to 228/343 rows backed
  (67% to 66%). The six new rows are the five planned ACs and the planned matrix row. That is the
  accepted spec-first precedent (IR #280).
- FR-014-AC-39, FR-018-AC-19 and FR-021-AC-21 are unchanged, and NFR-005-AC-1 does not contradict
  them. They count literals and, for FR-021-AC-21, test items, inside their own files. NFR-005
  bans more tokens everywhere else. FR-021-AC-21 is silent on `assert!` where NFR-005 bans it,
  which is narrower, not a conflict. So the oracle matrix rows marked covered (✅) stay true:
  their ACs and tests are unchanged.

## Verdict

The census is complete and correct, the token list matches, the IDs are clean and validation
does not change. Four medium findings must be fixed before merge:

- interface-001 does not list the new error variant.
- A draft PR changes the same corpus site in a way that conflicts with this one.
- FR-021's new sentence claims a scan that NFR-005-AC-1 does not perform.
- The Statement's purpose clause claims more than the Scope delivers.

Three low findings are optional.
