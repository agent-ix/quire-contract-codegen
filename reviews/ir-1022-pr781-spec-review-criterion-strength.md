## Summary

Ticket: IR-1022. Spec-only PR #781 (head 9c35b4fb, one commit on base dbb88103). It accepts an exhaustive concrete enumeration over the 1001 points of the Int[0,1000] clause as evidence in place of the Inconclusive/TimedOut symbolic Kani proof. It adds FR-015-AC-132 (the enumeration) and FR-017-AC-64 (its evidence record, with no terminal value) and a new FR-017 Behavior statement. It amends FR-015-AC-41, AC-119 and AC-126, FR-017-AC-60 and AC-63, AD-007, TC-025 (step 51), TC-027 and tests.md. Upgrade: IR-1509. Reviewed against CG source on base (src/kani/terminal.rs, src/kani/generate/clause/v2.rs, src/oracle/clause.rs, src/oracle/clause/native.rs, src/oracle/scalar/render.rs, tests/it/kani_obligations_state_frame.rs), open PR #583 (installed mutant controls), FR-029/FR-030, Linear IR-1022 and IR-1509, `make spec` and quire matrix. No cargo or Kani was run.

## Verdict

CHANGES REQUIRED. Jev (typesafe.ai System One) is not installed on this host, so this analysis was done by hand against CG source. Each AC-132 mutant was computed by hand against the actual oracle (src/oracle/clause/native.rs; short-circuit implication at src/oracle/clause.rs:721-728 evaluates the consequent only when the antecedent holds), the probe (src/kani/generate/clause/v2.rs:1184-1188, guarded by the antecedent) and the subject (implies_short_circuit; the oracle uses scalar_owner::evaluate_boolean_short_circuit, never the runtime helper, src/oracle/scalar/render.rs:274-283). Distinguishing as intended: helper=false fails at 0, because r=false while the native expectation is true. amount+1<1000 fails only at 999 (1000<1000). The antecedent <= 1000 fails only at 1000 (1001<=1000 false). amount+2<=1000 fails only at 999. The omit-999 enumeration fails the count. The kernel '+' mutants fail at 0 through the probe, but only at the installed-control site; see FND-001. Every mutant can fail once the site is fixed. Defects: the mutant site, 'only 999' not observable, the count-only acceptance, and the forbidden-wording rule.

| FND-001 | high | The mutant site is not determined, and under the literal text two mutants give the wrong failing input or cannot fail. AC-132 says each mutant is 'applied to the generated crate as the installed control applies it', and TC-025 step 51 says 'rewrite one expression of a copy of the generated crate per mutant'. The installed controls do not mutate the generated crate. The '+' mutants clone quire-exact and rewrite `left.0.checked_add(right.0)` in its src/native_integer.rs (#583, tests/it/kani_obligations_state_frame.rs:1176-1200), and the helper mutant edits an isolated quire-contract-runtime checkout (AC-119). The generated harness's probe calls nx::evaluate_native_integer_arithmetic directly (src/kani/generate/clause/v2.rs:1184-1188), not the embedded oracle's scalar_k (src/oracle/clause/native.rs:203). So, rewriting the embedded oracle's '+' in the generated crate: (i) '+ returning left' makes the consequent amount <= 1000, true over the whole domain. The oracle, subject, native expectation and kernel-calling probe all still pass, so the mutant is equivalent and cannot fail (FR-031 records this same drop-the-+1 mutant as equivalent). (ii) 'left + right + 1' fails at 999 through the clause oracle, not at 0. (iii) Rewriting the consequent literal 1 to 2 in the oracle likely trips the native plan admission (literal operand interval [1,1]) and stops at 0, not at 999. Done the way the installed controls do it (kernel '+' in an isolated quire-exact checkout, which the probe shares; helper in an isolated runtime checkout; consequent/antecedent in the QSL source, then regenerate), every stated failing input is correct by hand: amount+2<=1000 and amount+1<1000 fail only at 999, amount<=1000 only at 1000, helper=false at 0 (r=false against expectation true), kernel left+right+1 and left at 0 (probe 2 or 0 against 1). Fix: name the site of each mutant (QSL source, isolated quire-exact or quire-contract-runtime checkout) in AC-132 and in step 51, and say that (d) is the generated probe's kernel call (or that the test calls the embedded scalar_k). | spec/kani/functional/FR-015-bounded-kani-obligations.md:938 |
| FND-002 | medium | 'Fails at 999 and no other value' (AC-132, AC-60 amendment, step 51 'only there') cannot be observed as specified. 'In order' and 'no skipped value' are prose in AC-132, and nothing asserts them. Fix: require that the visited sequence is exactly 0, 1, ..., 1000 (each value once, ascending), and add a duplicate-and-skip enumeration mutant that this check must fail. | spec/kani/functional/FR-017-kani-execution-evidence.md:921 |
| FND-004 | medium | The forbidden-wording control is not mechanically checkable and conflicts with the PR's own text. Step 51 checks a different list (proved, verified by Kani) over 'every status line crediting it'. A grep test over those lines therefore fails on the healthy spec, or has to judge negation and context, and then a mutant that writes 'Proved' in the record render could be argued past it. Fix: name the surface checked (the printed record and the status column of the AC-132/AC-64 matrix rows), give one exact list of forbidden positive tokens, and make step 51 use the same list. | spec/kani/functional/FR-017-kani-execution-evidence.md:921 |
