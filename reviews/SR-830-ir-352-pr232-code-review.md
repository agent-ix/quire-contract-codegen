# SR-830: CG PR 232 code review

## Summary

Ticket: IR-352. PR: agent-ix/quire-contract-codegen#232 at e091c5a, one commit over base 2130cd9.
The `rust-review` lane is folded into this file.

What I checked:

- Panic removal. The diff removes 37 `unreachable!` lines and adds none. 35 were `_`/`&_`
  catch-all arms over Contract Runtime enums. Each now returns
  `OracleGenerationError::unknown_variant("<Enum>")`. The other 2 were the `(family, suffix)`
  string-pair catch-alls in `catalogued_operation` and `text_family_identity`. They are gone
  because `ordering_identity` and `comparison_identity` now match the typed
  `(operands, operator)` / `(family, operator)` pair directly. I checked the identity strings
  in the new tables against the old ones: the same 12 ordering and 18 comparison identities. In
  `scalar/` and `equality/`, the only `unreachable!` left are `ValueType::Quantity` and
  `ValueType::Reference` in `equality::render_value_type` (lines 1574, 1595). Both are named
  variants refused earlier in generation (module doc lines 66-72), not unknown-variant
  catch-alls. `function/mod.rs` keeps `IntegerOperator::Negate => unreachable!` (a generation-time
  refusal) and the two `Ok(_) => unreachable!` arms inside the emitted source string. The PR
  body reports all of these.
- RT enum facts. In quire-contract-runtime at the locked rev ccc722b, all 16 enums named in the
  diff are `#[non_exhaustive]` (IeeeWidth, IeeeComparison, QuantityTarget, OrderingOperator,
  ComparisonOperator, IntegerDomain, DivisionProfile, RoundingMode, TextProfile, IllTypedCause,
  RecursionEdges, DeclarationCause, EqualitySchedule, CompositeShape, ValueType,
  CollectionKind). So every converted arm is a real non-exhaustive catch-all.
- Byte identity of generated artifacts. Read from the diff: every changed `format!` keeps its
  template and arguments and only gains `?` or an `Ok(..)` wrapper. The composite and tuple
  `collect` paths build the same strings as `Result<String, _>`. `function/mod.rs` is not in
  the diff, so the emitted `Ok(_)` arms are unchanged. I also measured it myself: with an
  uncommitted `Artifact::new` dump hook (reverted afterwards), base 2130cd9 and head e091c5a
  produced byte-identical dumps of every artifact the scalar and equality integration tests
  generate. The result is in the gap analysis, SR-831.
- Error routing. In equality, `check_item` now returns `ItemCheckError`. A `Refusal` stays a
  per-item claim-map refusal. A `Generation` error aborts the whole call
  (`generate_composite_equality_oracles`). This matches the scalar generator's existing
  pattern and the `UnknownRuntimeVariant` doc rationale: a stale view of an RT type puts every
  item in doubt. The duplicate-copies branch in scalar collects identities as
  `Result<Vec<_>, _>` before `min`, so the result is the same on the Ok path. The
  `confirmed_identity` rewrite keeps the old `map`/`then_some` meaning. It is written as a
  `match` only so that `?` can escape to the generator.
- Rust idiom. The `TryFrom` mirrors use `type Error = OracleGenerationError` and keep the
  `Ok(match ..)` / `return Err(..)` shape. No `unsafe`, integer-conversion or async surface
  changed. `IllTypedCauseKind`, `RecursionEdgesKind`, `DeclarationRefusalCause` and
  `RecordedSchedule` are re-exported from `src/lib.rs`. Dropping their `From<rt::..>` impls is a
  public-API break. No code under ~/dev outside this repo uses them, and the crate is
  prerelease, so this is not a finding. `scalar::ItemCheckError` and the new
  `equality::ItemCheckError` are two copies of the same two-variant enum. That duplication is
  noted here, not filed as a defect. The test-module change (`.expect` on the new `Result`
  layer of `catalogued_operation`) keeps the existing assertion.
- Gates on e091c5a (my run, log `cg-ir-352-ci.log`): fmt, clippy `-D warnings`, deny,
  audit-unsafe, rustdoc and the MSRV and stable test suites all pass. Details and the host
  Makefile quire-path note are in SR-831.
- PR title: "Return UnknownRuntimeVariant instead of panicking on unknown RT enum variants". It
  has no bare ticket id. The body says "Partial for IR-352 ... Does not close the ticket."

## Verdict

The conversion is correct and complete for the scalar and equality generators. No panic that
the PR says it removed is still there. Generated bytes are unchanged, by reading the diff and
by my own measurement. Two low findings, both about documentation and consistency.
