# SR-1485: CG PR 271 spec review (base)

## Summary

Ticket: IR-465 (code half), with IR-611. The spec part of this PR is status and interface prose
that follows the code. It adds no new requirement and no new criterion. `make spec` passes on
the head as part of `make ci`.

Checked:

- interface-001 `run_terminal_value` row. The inputs, outputs and semantics match the signature,
  `ReplaySettlement`'s six variants and `TerminalPairError`'s two. The `ReplayPackage::new` row
  drops the manifest digest and `Duplicate`, and `replay_counterexample` gains the disagreement
  cause. All match the code.
- FR-029 Status. It is accurate (see SR-1484 for the coverage measurement). The QSL facts it
  states hold at 02530e7: `TerminalValue::Inconclusive`, `InconclusiveCause::{ReplayParity,
  ReplayRefused(Code)}`, `Declined { cause, code: DeclineCode }` with only `Qsl(Code)`, and
  `from_replay_refusal`.
- FR-030 Status and TC-041. "No total map is buildable" is true. The map must produce `Declined`
  with a `DeclineCode` for IR's `kani_*` causes, and QSL has no IR arm yet.
- TC-040 Status and the matrix rows. They agree with the tagged tests.
- AD-003 and AD-004 (the merged architecture statements). The design they describe matches what
  the code now does. `kani/terminal.rs` defines a replay-settlement type from `qsl-replay` types
  plus CG-raised variants, `replay/` imports `kani` and owns the conversions, and `kani` imports
  nothing from `replay`. A fault is `Failed`, a coded setup refusal after a refutation is
  `ReplayRefused`, and `Declined` is never produced. The `backend` member carries no digest. But
  both ADs still state, as current fact, things this PR makes false (FND-001).

## Verdict

The edited documents are accurate. The architecture documents the PR did not touch now
contradict it in their status sentences. That is a small, prose-only fix inside this PR.
