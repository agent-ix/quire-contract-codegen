# SR-1374: CG PR 256 spec review (EARS conformance)

## Summary

Ticket: IR-465. Each added or edited requirement statement was read for the EARS form. The repo's
form is "The Kani adapter / The generator shall ...", plus prose rationale bullets. The edited
Description sentences and these bullets are ubiquitous EARS with one actor and one response: "map
... in exactly one function, public so the driver calls it", "map each pair as the table states",
"map a falsified outcome to `Refuted` only with a reproduced replay", "classify a fault by walking
the whole error", "expose no `proof_category` function", and FR-030's `Counterexample` and
`proof_category` bullets. The new ACs are concrete, single-result and testable.
