# SR-1447: CG PR 265 spec review (base)

## Summary

Ticket: IR-465. Base checklist over the PR diff: id hygiene, AC to TC trace, matrix rows, status
honesty, provenance of the relayed QSL ruling, and the evidence the PR gives for its new
classifications. The QSL ruling was read from the planner's relay comment on IR-465 (a peer
report). The QSL source was re-measured at origin/main.

Measured:

- New ids FR-029-AC-14 and FR-030-AC-13 appear only in the PR commit (`git log --all -S`), so
  they were never issued before.
- `quire coverage` shows 398 rows at base and 400 at head. FR-029 goes from 0/12 to 0/13 and
  FR-030 from 0/12 to 0/13. `quire matrix --strict` shows 137 untagged criteria at base and 139 at
  head. The +2 are exactly the two new held rows, so the count is honest.
- TC-040 steps 12 and 13 trace to FR-029-AC-13 and AC-14. TC-041 steps 11 and 12 trace to
  FR-030-AC-12 and AC-13. The tests.md matrix and index rows list the same ids. The planned
  markers are honest.
- QSL merged state: `TerminalValue` has seven variants, `Declined(ProofRefusalCause)` carries
  only the cause, `InconclusiveCause` has only `KaniVacuousProof`, and `Proved` holds a `u32`.
  `CallSiteRefusal::code()` and `DependencyInputRefusal::code()` are public. The FR-121 text
  still says `declined` unconditionally. The Status sections state all of this, and say the code
  half waits on QSL-351.
- `make spec` exits 0 in this fresh worktree (warnings only, no archetype failures).

## Verdict

The base checklist passes on ids, trace, matrix and status honesty. There are three low
findings: the provenance of the relayed ruling, a factual slip in the `InvalidFunction`
rationale, and one stale AD-003 paragraph. None blocks the merge.
