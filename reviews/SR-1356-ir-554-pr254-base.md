| FND-001 | low | "claims no case identity, so the same request is still emitted once with the matching input" does not follow. The matching-input request is a different case identity, because the input's profile selection is part of the identity, so it is emitted whether or not the refused call claimed anything. The "so" clause cannot show the "claims no identity" claim, which is why the test that backs it is vacuous (SR-1354 FND-001). State the identity property alone, or drop it | spec/kani/matrix/TC-023-bounded-kani-profile-corpus.md:50-53 |
| FND-002 | low | The new clauses (mismatch refusal, revision context) have no owning requirement. TC-023's matrix row maps it to FR-015-AC-23, which is about `ObligationDisposition` and names TC-025 as its verifier, and no FR-015 AC mentions the bounded corpus, a profile/input mismatch, or outcome context. The mapping was already loose before this PR, but the PR adds to it. It needs a follow-up AC, or a ticket recording that the corpus has no owning AC | spec/kani/matrix/tests.md:44, spec/kani/functional/FR-015-bounded-kani-obligations.md:262 |

## Verdict

Both sentences are clear and atomic enough to test, and the code matches them (SR-1355). Two
lows: a causal clause that does not follow, and no owning AC. The `🚧 Planned` status is
honest. Neither finding blocks a merge alone.
