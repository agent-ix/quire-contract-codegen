## Summary

Spec-only PR #782 (head e28c9528, one commit) records the owner's minimal Kani run ownership decision: new ADR-007 (Accepted) supersedes ADR-005; FR-034 and TC-049 are deleted; FR-017-AC-65/66/67 and FR-028-AC-25 are new; FR-017-AC-19 is rewritten to the launch-unique named report file; FR-017-AC-54/55/56 are retired; FR-028-AC-21 is made environmental; TC-039 steps 23-26 and TC-043 steps 15-17 are added. No cargo and no Kani were run.

## Verdict

CHANGES REQUIRED. Removing the namespace takes away guarantees it used to give implicitly: escaped descendants were reaped, process identities were pinned by pidfd, and every memory stop was observed. The spec accepts caller-death orphans explicitly, which is the owner's decision. It does not state the other losses, and one ADR statement is wrong.

## Findings

| --- | --- | --- | --- |
| FND-001 | medium | ADR-007 says a caller killed after launch 'leaves a Kani process group running until its own wall-clock bound or the environment's cleanup ends it'. The wall-clock bound is enforced by CG, in the caller. FR-017:742-744 states that the generator passes --harness-timeout only to a batch, so an orphaned single run has no bound at all, and a batch's Kani-side bound is per harness (up to N x T). Fix: state that an orphaned single run is unbounded unless the environment ends it (a batch is bounded by --harness-timeout per member), or pass --harness-timeout to single runs as well. | spec/decisions/ADR-007-minimal-kani-run-ownership.md:58-60; spec/kani/functional/FR-017-kani-execution-evidence.md:742-744 |
| FND-002 | medium | ADR-007 Decision 1 promises that the group kill leaves 'no started process'. A descendant that calls setsid or setpgid leaves the group and survives. launch.rs:996-997 documents this ('A descendant that leaves the group ... is not reached'), and the namespace design caught it (TC-039 Status listed session-escaped-child fixtures). Fix: scope the claim to processes in the launcher's group, as FR-017's existing statement does, and record the escape as an accepted cost beside caller death. | spec/decisions/ADR-007-minimal-kani-run-ownership.md:43-46; src/kani/run/launch.rs:990-1005 (origin/main) |
| FND-003 | medium | Process-group id reuse is not covered. Without pidfd and the namespace, killpg is safe only while the leader is not yet reaped, because the zombie keeps the id reserved. Current code does this with waitid(EXITED\|NOHANG\|NOWAIT) before the kill (launch.rs:692-694, :813-815). No statement or AC requires that order, so an IR-1510 rewrite that reaps first (Child::wait, then kill_process_group) could signal an unrelated group that reused the id. Fix: add a statement that the group is killed before the leader is reaped, with a mutant that reaps first. | src/kani/run/launch.rs:685-700,813-815 (origin/main) |
| FND-004 | medium | An environment memory kill can map to Failed, and the spec does not say so. A cgroup kill that takes kani-driver as well as CBMC (memory.oom.group, or systemd OOMPolicy=stop on the unit) leaves no report. AC-25 makes that NoVerdict, and FR-029 maps NoVerdict to TerminalValue::Failed (terminal.rs:147-151), not Incomplete(ResourceExhausted), so the same exhaustion gets a different value depending on what the environment killed. FR-029-AC-34 ('one exhaustion has one value whoever observed it') then no longer holds. A unit stop can also kill the caller, so no classification happens at all. Fix: state the terminal value of a no-report environment kill and whether Failed is accepted, and amend FR-029-AC-34. | spec/kani/functional/FR-028-bounded-proof-ceilings.md:229; src/kani/terminal.rs:147-151 (origin/main) |
