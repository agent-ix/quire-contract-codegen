## Summary

Code review with the Rust lane of PR #190 (branch `chore/remove-digest-provenance-ceremony`, 3 commits, 20 files, +59/-52) against `origin/main` 6f4beea, which is the merge base. No ticket id is derivable from the branch or title.

The PR deletes `ProfileSelection.executable_digest` and `options_digest` at all seven construct sites, deletes the `Generated by quire-contract-codegen {version}; DO NOT EDIT.` line from nine generator headers, drops the schema pattern that required it, and moves `quire-contract-ir` from 48ab5dc to 37c34de. Three test fixtures change to meet IR #205's stricter V2 reader.

## Verdict

**PASS**, with two low findings in test-support comments and constants.

Clean, and recorded as examined:

- No text that reads the removed fields or the stamp remains. `git grep` for `executable_digest`, `options_digest`, `DO NOT EDIT`, `Generated by quire-contract-codegen` and `CARGO_PKG_VERSION` at head finds matches only in historical `reviews/` files. No substitute stamp was added. The three `// @generated by quire-contract-codegen ... Do not edit.` lines (src/composite_equality.rs:1286, src/exact_function.rs:1225, src/exact_scalar.rs:2337) are on main unchanged, carry no version, and are not what this PR set out to remove.
- The schema change removes exactly one `allOf` pattern plus its words in `description`. The SPDX, identity, clause and oracle-signature patterns are unchanged.
- The source-map test still tests behaviour. tests/it/oracle_generation.rs:506 moves the consequent line from 21 to 20, and :507-514 still asserts that the line at that index is the text `false`. A wrong source map still fails.
- Bare `state` blocker `state_clause` → `snapshot` (tests/composite_equality_support/package.rs:788, tests/exact_scalar_support/package.rs:2750). IR 37c34de now validates `state_clause` bodies (a `quire.op.state.clause` application, role `claim`), so an empty-aggregate `state_clause` no longer admits. `snapshot` stays unvalidated in the IR. The codegen refusal keys on the node tag only: src/exact_scalar.rs:908, src/composite_equality.rs:868, src/exact_function.rs:570 and :639. The kani classifier special-cases only `state`/`frame` (src/kani_obligations.rs:1095). The assertions are unchanged: tests/it/exact_scalar_generation.rs:412 (`Unsupported`, tag `state`), tests/it/composite_equality_generation.rs:492 (`QuireSpecLanguage121`), and tests/it/kani_obligations.rs:862-867 (`NoFiniteEncoding`, tag `state`). The refusal is still exercised. The test does not pass vacuously.
- The occurrence roles (tests/exact_scalar_support/package.rs:466-470): IR 37c34de structural.rs fixes `parameter` → `expression` and `frame` → `generated`. The fixture now emits those roles on the node and on the source-map entry. No codegen src reads occurrence roles for these forms.
- The frame retype (tests/it/kani_obligations.rs:434-447): IR 37c34de frame.rs requires a frame's `semantic_type` to be a `model`/`object_type` node. The fixture adds one. The FRAME assertions at :868-878 (kind `Frame`, `NoFiniteEncoding`, a non-empty source map) are unchanged.
- Other IR 48ab5dc..37c34de API changes: `run_manifest`→`run_corpus`, `hex_digest`, `GeneratorProvenance`/`ArtifactIdentity`, the modules `bridge`/`predicate`/`temporal`/`ecosystem_model`, and three `ModelForm` variants were removed. Codegen used none of them (grep on main). The build compiles and clippy is clean, so nothing was worked around.
- Cargo.lock: codegen's IR now resolves `quire-contract-model` 37c34de, while `qsl-package` (through `qsl-replay` 1a368fa) keeps 48ab5dc. The two are separate crates in the graph. src/spine_replay.rs crosses the boundary only by transcript text and `WitnessValue`, so no type mismatch is hidden. This split follows from QSL's own pin and is not a defect of this PR.
- Gates at 90a1091 (own logs): fmt-check, lint, test and spec all EXIT=0. The spec warnings are identical to main: the FR-014 line 267 EARS warnings are on both.
