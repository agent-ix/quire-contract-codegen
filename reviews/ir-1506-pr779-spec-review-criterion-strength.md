## Verdict

FAIL ON MEDIUMS (manual: Jev is not available here, so each mutant was traced by hand to an input). The AC-13 mutants (a) to (e) all distinguish, can all be built, and each names a failing input that step 13 runs. Checked on host data: (a) a 16-byte nfc payload retains two scalars or is invalid; (b) and (c) U+FDFA, whose nfkd retains 18 scalars under nfkc and nfc; (d) one unit retains 1 < min 2; (e) U+00C0 at 3 bytes against 12. The tie mutant is correctly not claimed. The final-byte pair at L is a control that can fail and is satisfiable. Three weaknesses remain: the first-byte absence carve-out can never fail, the AC-12 loop mutant is not distinguishing for nfc/nfkc, and AC-13's equality assertion is wrong for binary-utf8.

| FND-001 | medium | The first-byte pair absence rule applies to every profile, and nothing requires the pair to be found where it exists. For binary-utf8, unicode-scalars, nfd and nfkd, changing the first byte to another valid ASCII or lead byte keeps admission. A host search that always returns none therefore passes and silently drops every first-byte control. The final-byte rule is a control that can fail and keeps the AC falsifiable for its named mutants, but the first-byte clause is not. Limit the absence rule to nfc and nfkc, or require the pair to be found for the other four profiles. | spec/kani/functional/FR-052-text-scalar-harnesses.md:298 |
| FND-002 | medium | 'A replacement whose ordering loop stops at L - 1 (or earlier) fails the final-byte pair of the length-L payloads' holds only when the retained sequence spans the payload. For nfc and nfkc, compare_text orders the retained sequences, which are 4 x max bytes (one U+16126 or U+16128 per unit) against L = 12 x max. An ordering loop bounded at L - 1 never truncates them, so the mutant survives the nfc/nfkc pair. For those profiles, name a payload-side loop (decode or normalize-input) bounded at L - 1 as the mutant the pair kills, or limit the claim to the four profiles where A = P. | spec/kani/functional/FR-052-text-scalar-harnesses.md:298 |
| FND-003 | medium | 'The check asserts ... that A equals max times the enumerated maximum byte length of one stable scalar's decomposition' does not say which profiles it covers. For binary-utf8, A = max (ASCII bytes), while the stable-scalar decomposition maximum is 4 bytes, so the assertion as written fails a correct implementation (TC-066 step 13 repeats it unscoped). Limit it to nfc and nfkc, or define the per-profile enumerated unit (1 byte for binary-utf8, 4 bytes otherwise). | spec/kani/functional/FR-052-text-scalar-harnesses.md:299 |
| FND-004 | low | Mutant (a) builds 'the payload of P bytes (the unit extended to P bytes)' but does not say how the unit is extended. Appending a scalar is refused by TextType::admits (two retained scalars), while padding with continuation bytes is refused earlier by from_utf8, which is a different check than 'the admission check' named. State the extension (for example, append one four-byte self-normal scalar). | spec/kani/functional/FR-052-text-scalar-harnesses.md:299 |
