## Summary

Ticket: IR-1520. PR #795 (spec only, one commit aab0b8e1 on origin/main e75918f4, branch spec/ir-1520-postcondition-identity) implements the code lead's Option A for the postcondition/frame lane. It adds FR-015-AC-137, FR-024-AC-67 and FR-024-AC-68, a closure paragraph on the FR-015-AC-48 PARTIAL note, a pointer sentence on FR-024-AC-65, TC-025 step 54, TC-035 step 47 with its status sentence, and the matrix rows in spec/kani/matrix/tests.md and spec/replay/matrix/tests.md. Reviewed read-only against the code at origin/main (src/kani/generate/frame.rs, src/kani/identity.rs, src/kani/generate/negotiate.rs, src/kani/generate/outcome.rs, src/routed/capability.rs, src/replay/state_clause.rs, src/replay/frame.rs, src/replay/obligation.rs), the pinned qsl-replay at 434869e, interface-001, the open PRs #794 and #796, and the IR-1520 decision comment. No cargo or build was run. `quire validate` (make spec equivalent) on the branch reports 6 warnings, the same 6 as origin/main; `quire matrix` lists FR-015-AC-137, FR-024-AC-67 and FR-024-AC-68 as untagged, as expected for PLANNED criteria. Method: spec-review/base.

## Verdict

**CHANGES REQUIRED.** The premise checks out against the code: the postcondition/frame lane has no identity today, `StateClauseReplayInputs` already takes `obligation_identity`, and `StateClauseReplayError::ObligationIdentityMismatch` exists and settles as `CgDefect` (FR-029-AC-16), so the AC-67 order (after `NotPostconditionHarness`, before the `HarnessMismatch` loop) is implementable and consistent with AC-65 and the AC-62 closed set. But the frame role is specified onto a function that refuses frame harnesses first (FND-001), the frame replay path is left out while AC-48 closure claims every path is covered (FND-002), and the public negotiate item that builds `StateFrameRequest` is not given an identity source (FND-003).
