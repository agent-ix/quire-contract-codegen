# Base review of the numeric/state strategy slice

## Summary

ID formats, AC numbering, and all 17 changed files' relative links are clean (0 broken links), and every FR AC maps to a TC row in the matrix. The IR names hold up against quire-contract-ir 04eb6f8: `IntegerType`, `OverflowPolicy`, `StateObservation`, `ComparisonOperator`, `ExecutionPoint`, `ValueDeclaration`, `DeclarationEnvironment`, `TypedExpression`, `ClauseRef`, `BoundPackage` and `SymbolName` all exist. Three contradictions block implementation. The SL `amount < 7` fixture is anchored at `Handler`, so this slice would refuse it. Pre-anchored rejections are proptest global rejects, so "zero global rejects" cannot hold. And Post values are both generated and produced by the subject. Several names the spec relies on also do not exist at the pinned revisions (`deref`, `reaches`, `And`, `ExpectationMismatch`, a runtime observation kind).

| FND-19001 | high | SL's `integer-healthy` clause `amount < 7` is `ClauseKind::Invariant` at `ExecutionPoint::Handler { validate }`, with `amount` a `State` read at `Current` (quire-spec-language tests/support/standalone_setup.rs:79 and runtime_setup.rs:56-61). FR-011:43 and FR-011-AC-5 refuse `Handler` with `UnsupportedAnchor`, and the interface lists that refusal among generation refusals, so the fixture that FR-008-AC-2 (FR-008:83), FR-009-AC-4, FR-010-AC-1 and TC-020:22 ("`Pre`-anchored `amount < 7`") depend on can never be admitted. Fix: either replace it with a codegen-built `Pre`-anchored `amount < 7` fixture and drop the "SL's `integer-healthy`" attribution, or specify the `Handler`/invariant verdict mapping and remove `Handler` from FR-011-AC-5. | FR-008-AC-2, FR-011-AC-5, TC-020 |
| FND-19002 | high | interface-001:117 `discard_boundary` says a precondition rejection is a proptest global reject counted in `rejected`. A `Pre`-anchored `Violating` or `Broad` campaign (FR-011:37-39) therefore always produces global rejects, and at proptest's default `max_global_rejects` a 10,000-case run ends `Exhausted`. That contradicts NFR-004:41-42 (global rejects = 0, `Exhausted` = 0), FR-009-AC-3 (FR-009:62) and TC-018:22. Fix: restate the metric as generation-time rejects only, excluding verdict-driven `RejectedPrecondition` rejects, or require the runner to raise `max_global_rejects` and measure `Exhausted` separately; apply the same change to FR-009-AC-3, NFR-004 and TC-018 step 2. | NFR-004, FR-009-AC-3, TC-018 |
| FND-19003 | high | The `Post`-anchored campaign model is inconsistent. If the post value is generated, the subject cannot affect it; if the subject produces it, it is not a generated read. Fix: state in FR-011 whether `Post` reads are generated inputs to the oracle (no subject) or observed subject outputs (only `Pre`/`Current` generated), and align FR-009, FR-012-AC-3 and TC-020 step 1. | FR-011-AC-1, FR-009-AC-1, TC-020 |

Fix: refuse every non-`Integer` read (Boolean included) with `UnsupportedDeclarationType`, add that clause to FR-008-AC-4, and rename the TC-017 fixture to `Text`. | FR-008-AC-4, TC-017 |
